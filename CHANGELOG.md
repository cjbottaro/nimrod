# Changelog

Notable user-visible changes to Nimrod. **Unreleased** describes development changes, not an available public release. See [Contributing](CONTRIBUTING.md#changelog-and-local-development) for the maintenance policy.

## Unreleased

### Added

- Copilot `/skills info` now completes the CLI's omitted skill-name interaction with a searchable harness-owned skill picker sourced from Copilot's public session catalog, then invokes the original slash command. `/skills list` and other read-only report commands continue through generic command output. Native acceptance is pending.

- Copilot SQL cards show the agent's description, concise literal results and optional reported statement/row counts, with original SQL and metadata retained in raw disclosures. They do not parse SQL into a task checklist. A [built-in card cookbook](docs/builtin-card-cookbook.md) documents Pi/Copilot presentations with real-session prompts, prerequisites and expected outcomes. New capture-backed fixtures are authored but unrun; native visual acceptance remains pending.

- Ordinary modals now apply in-app depth blur to the Nimrod content beneath them, including the first modal over the conversation and nested modals over lower dialogs, on supported translucent macOS windows. The CSS renderer follows the same effective 0–40 strength, live preview, Off/opaque and Reduce Transparency behavior as native background blur through one explicit mapping; AppKit and CSS remain perceptually calibrated rather than pixel-identical. Linux compositor blur cannot expose a portable strength to the webview, so modal depth blur remains off there pending an explicit app-owned contract and WebKitGTK verification.

- Global Appearance typography controls provide separate conversation/composer and code/tool-output fonts and sizes, searchable installed-font pickers with family samples and monospace-first ordering, a live preview and reset to system defaults. Choices synchronize across projects and pop-outs without changing interface typography or zoom; missing fonts keep their saved choice and use portable system fallbacks. Native macOS/Linux acceptance remains pending.

- Completed Copilot questions show a compact question/answer transcript card: a speech-bubble icon beside the question and an inset reply with a theme-accent line using the app's compact nested-quote spacing. Offered options appear as a numbered list in conversation typography, with exact raw inputs/output behind the disclosure; the separate Question picker is unchanged. Native visual acceptance remains pending.

- Composer keyboard hints brighten while their exact modifier keys are held in the focused prompt field, with no animation or layout shift. Shared hint metadata supports all integrations without inventing unsupported shortcuts; focus loss, session switching and input locks clear the emphasis.

- Copilot image paste, including image-only messages, shared thumbnails/drafts/auto-follow, in-place user-echo adoption and restored inline images. Model-advertised image support and limits are respected; busy sends keep the draft without inventing steering or queueing. Unavailable saved image bytes remain explicit. New offline fixtures are authored but unrun; installed-CLI and native macOS/Linux acceptance remain pending.

- Session pinning keeps chosen sidebar rows above unpinned sessions, with saved open-session pins remembered per project. Pin/Close controls reveal on hover or keyboard focus; pinned rows keep their pin visible. Native right-click menus offer Pin/Unpin, Close and capability-aware Delete for the clicked session without selecting it; Delete moves out of the inline row controls. Pin/Unpin is also a bindable command-palette action. Pinning and startup restoration prefer the top of the sidebar, scrolling only enough from the top to fully reveal a deeper target; unpinning preserves normal reading-position anchoring, and hidden/filtered targets do not scroll. Native macOS/Linux acceptance is pending.

- Copilot **Select permissions… → Allow all** and `/permissions allow-all` use a live **PERMISSION CHANGE** operation card when the runtime advertises active-turn support. Permission policy applies independently of queued model changes without stopping/resending the task or answering older approvals; native policy controls subsequent requests. Independent configuration owners share the existing picker/cards so future integrations can contribute the same capability without backend-specific UI changes. Other permission commands queue for idle execution; native acceptance is pending.
- Configurable modal motion in global Appearance: **Subtle** fade/lift/scale and **Pixel dissolve** shuffled tile assembly with configurable pixel size, per-tile content blur and fading use a duration slider (default 500 ms); **CRT power-on** center-out scan (default 500 px/s) and **Hologram** top-down accent scan/trail (default 1000 px/s) use scan speed. Scan speed is independent of modal size and filtering retargets pixel edges without changing velocity. Pixel dissolve reverses on close, handles partial reveals without flashing the full panel, and completes immediately if filtering changes its opening layout. Duration/speed are remembered separately. Preview supports Close/Escape, reduced motion disables effects, and input/focus/settlement stay immediate. Inert exit copies animate after real closure and are cleared by new dialogs.

- Copilot plan review supports optional feedback and **Request changes**, returning revisions through the plan decision rather than sending another prompt or replacing the composer draft.

- Copilot SDK cards for GitHub MCP code-search results and repository contents, skill-name previews, and compact command/file/URL/MCP permission details with raw recovery.
- Choose model/thinking settings while connected even when the harness must wait to apply them. Deferred changes use one Queued/Steering-style shimmering transcript entry that updates in place when you choose again; the Status area shows only confirmed values, with no pending badge. Pi retains changes during work/compaction; Copilot applies at idle. Model/effort dependencies are revalidated and pending intent is cancelled on disconnect rather than replayed.
- Copilot session configuration now includes **Interactive**, **Plan** and **Autopilot** modes plus default/long context-window tiers. The Status area extends `model · effort` with mode, and the reported context limit opens **Select context window…** when that session supports changing it. Plan completion choices stay in the owning conversation.
- Copilot web-search cards with formatted answers, numbered citations and source titles/domains; fetch cards with compact linked page URLs, readable page/raw-source content, visible redirects/truncation/errors, and literal SDK permission requests. Web sections use compact headings and wrapping text/links. Web links open through Nimrod’s existing handler; original output remains available in Raw output.
- Compact Copilot cards for file reads, text searches and filename-pattern searches, with project-relative paths inside the project (absolute paths outside), path-then-line-range read summaries, query-first search summaries and cleaner plain-content results backed by exact raw-output recovery. Shared read/search presentation helpers are also available to external card plugins.
- Opt-in **[Transcript debug logs](docs/transcript-logs.md)** in global Diagnostics replace tool-only capture with full native conversation, history and request traces. Logs stay local with automatic rotation/retention; existing opt-ins are preserved and explicit setting changes migrate to the transcript-logging preference. One native writer consumes a bounded shared queue; producers wait instead of stopping capture on bursts. Sustained waits show one automatically resolving warning that debug logging may slow session processing. Large events stay whole rather than requiring chunk reconstruction; actual storage failures remain separate errors.
- Built-in **New Copilot session** uses the bundled official SDK 1.0.22 with your installed/authenticated CLI (declared compatibility: 1.0.98) and supported Node. SDK sessions reuse the shared transcript, drafts, permissions/questions, tools, notifications and model/thinking controls, with exact-ID Resume and confirmed-only permanent SDK deletion. Close preserves history/drafts; failed or uncertain sends/deletes never replay. The previous Copilot integration is removed; its old stored drafts/history are not deleted or migrated. Harness labels are simply **Copilot**, and the new-session hint is concise. Pi stays the default for New; generic ACP infrastructure remains internal, with no palette creation/options actions, keybinding entries or restored ACP sidebar sessions. SDK fixtures, packaging and native macOS/Linux acceptance are pending; Windows SDK launch, SDK/ACP Restart and ACP images remain unavailable. Copilot slash commands are discovered/invoked through the SDK, with aliases, advertised argument hints/choices, harness-requested modal selections and labelled transcript output; new commands using supported result/effect kinds need no command-specific handler. Because CLI 1.0.98's bare `/model` and `/models` SDK invocations omit the terminal picker and exact catalog input completes without switching the live session, Nimrod supplies Copilot's enabled-model catalog before invoking the original command, then completes an exact catalog selection through Copilot's SDK and authoritative reconciliation; this remains independent from Nimrod's model action. Model and Plan-model effects complete through the harness transaction, including live model/effort application, authoritative reconciliation and SDK persistence finalization. Unknown/unsupported operations never fall back to chat; model-enabling and unknown dialog/effect kinds fail explicitly. Command fixtures are authored but unrun; native acceptance remains pending.
- Public card-plugin presentation/shell-output helpers, explicit harness/agent targeting and mount-time applicability, preserving legacy plugins as Pi-only by default.

### Changed

- Completed Copilot slash-command cards now remain immediately before the output they produced instead of settling below that result. Pending placement, reader position, focus and command execution are unchanged.

- Nimrod is now licensed under GNU AGPLv3 only instead of MIT. Third-party licenses and previously granted MIT permissions are unchanged; see [License](README.md#license).

- Copilot questions now use a sequential Question picker instead of an inline form above the composer. **Enter your own answer…** opens a nested input modal, like permission denial feedback. Escape dismisses without answering; a session-local **Answer question** banner reopens pending questions. Drafts stay untouched, and background questions never replace another dialog. Native acceptance remains pending.

- Translucency always applies to the whole window: translucency controls now consist of background opacity and blur, with no area selector. Legacy sidebar-only settings are ignored without rewriting the settings file; 100% opacity and Reduce Transparency keep windows opaque.
- Configuration changes and Pi steering/queued messages share Operation cards: stable uppercase titles, a shimmering bottom-pinned stack while pending, and normal transcript flow on completion. Steering now pins too; delivered steering/queued turns retain their runtime titles. Failures use red accents and error disclosures; unknown/not-applied outcomes use grey accents and optional details without duplicate banners. Safely withdrawable configuration changes offer Cancel in the card and command palette; Pi messages do not imply unsupported individual queue cancellation.
- Copilot permissions use a sequential command-palette-style picker with a remaining count and no close/reopen between decisions. Escape dismisses without answering; a persistent session-local **Review requests** banner reopens the queue. Denial feedback uses a nested input modal without resizing the picker. Scope-labelled choices can remember file access, reported command identifiers, exact MCP tools or URL domains for the session; URL-domain approvals can explicitly persist across sessions. Search requests use accurate titles, and the ambiguous permission Cancel request button is removed. Managed/sandbox-escalation requests remain one-time only; directory-only/saved-project grants and native acceptance remain pending.
- Independent errors/warnings now appear as separate, deduplicated banners with their own actions and dismiss controls, rather than collapsing behind a count/disclosure. The pending-permission banner stays first above the independently scrolling session error list; session/application ownership and per-banner Details remain unchanged.
- Palette and shortcut availability now distinguish application, project and selected-session actions. Project actions such as New remain available with no selected session; harness-specific actions appear only when the selected session contributes them.
- Model and thinking-level actions now use consistent descriptions across Pi and Copilot. Model pickers remove numbered prefixes and use stable model identities: Copilot shows friendly names with model IDs as detail, while Pi shows reported names with providers as detail.
- Copilot's Status area shows estimated USD equivalent of reported session AI credits and compact context utilization (`25.5% / 125k`), with AIC totals, coverage and full context counters in the tooltip. Fresh sessions keep provisional zero cost/utilization across empty startup reads until the first valid Send or live agent activity; reported values and actual errors replace the corresponding seed. Resumed sessions start unknown and share the same metadata update path. Missing fields use `—`, partial totals stay qualified, and optional usage reads never block chat.
- ACP command permissions use a compact **Run command · description** summary, exact command previews without duplicate metadata, and collapsed raw details below the existing permission buttons. Long descriptions wrap without truncation; unsupported operations retain the literal fallback.
- Experimental ACP plugins distinguish tool names (`tools`) from protocol categories (`kinds`); early POC category-based plugins must move their matching to `kinds`. Agent-specific matches take precedence over generic ACP matches.

- macOS release downloads and Homebrew installation target Apple Silicon only; Intel downloads are not provided.
- GitHub release notes use reviewed changelog entries, with Unreleased snapshots for prereleases.

### Fixed

- Advertised Copilot slash commands, including `/allow-all`, now queue while the agent is working instead of rejecting the submitted draft. Commands execute once in FIFO order at terminal idle, with pending operation cards; switching sessions, Stop or disconnect withdraws undispatched commands without replay. The existing `/permissions allow-all` live-policy path remains independent. New offline fixtures are authored but unrun; native acceptance remains pending.

- Keep Pixel dissolve's fade mask aligned with the full modal at different zoom levels, avoiding an undersized reveal that pops to the final size when the effect ends. Decorative animation layers fill their viewport without oversizing it.

- Image messages retain transcript auto-follow when decoding expands the turn after sending, including delayed old-bottom scroll events arriving after Send's follow frames, without overriding later upward scrolling. Pi's image coordinate-scaling notes are hidden in user turns; prompts and saved history are unchanged.

- Session deletion review no longer shrinks or recenters when confirmation switches to stopping/deleting progress; the disabled Delete label and reviewed description's layout footprint stay stable until the shared animated close.

- Appearance sliders show their theme-accent filled track immediately on opening Settings and after external value/theme changes, rather than waiting for the first adjustment. Duration, background opacity and background blur share the same track presentation; keyboard and save/preview behavior are unchanged.

- macOS background opacity and blur are independent: a 0–40 blur slider replaces the tinted frosted-material toggle, preserving sharp transparency at zero blur. Both sliders preview across windows; older frosting settings remain compatible. Blur-only changes no longer reapply the native theme/title tint, and a practically transparent backing keeps the normal macOS shadow path instead of the fully clear backing implicated in square-backdrop artifacts. Replaced the native radius setter that flashed grey when enabling blur with a tint-free material-backed effect covering content and the native title bar. Zero removes the effect completely; native layer-rebuild failures fall back to plain transparency with a window-scoped notice. Linux blur remains compositor-controlled.

- Copilot `/permissions allow-all` now enters the live permission-change path instead of reporting that Copilot must be idle. Command recognition, native admission and fixtures use the runtime's advertised `allow-all` spelling, correcting the earlier `allow-any` mismatch.
- Accepted configuration cards stay in normal transcript flow instead of following new output at the bottom. Changes confirmed before the first message remain at the start; coalesced updates and background sessions preserve the confirmation-time position.
- Copilot no longer offers or accepts session-wide shell/file-write approval when the runtime disallows it or omits its capability flag. Shell session choices use a concise label with parsed command context and exact approval scope in searchable secondary details, without implying arbitrary-argument access or broadening the returned identifiers.
- Copilot context-window changes refresh usage after configuration settles rather than caching an intermediate budget under the new tier. Long context keeps the model’s advertised maximum in the picker, and pending-model details no longer reuse another model’s limits.
- Copilot Autopilot keeps Working state, pending questions, tool cards and queued configuration across intermediate idle events instead of prematurely announcing completion. Explicit aborts finish as Stopped, repeated terminal events do not repeat completion, and plan approvals are validated against the owning request's offered actions.

- Copilot model, thinking-level, mode and context-window changes no longer fail with “Unsupported Copilot SDK bridge operation” and disconnect the session before reaching Copilot.

- Copilot's built-in GitHub MCP web searches now reach the rich answer/citation cards instead of the generic MCP fallback; unrelated MCP query tools retain their own presentation.
- Reopening a project now reconnects its last selected Copilot session through the shared selected-session lifecycle, without sending a prompt or connecting other restored Copilot rows.
- Model-picker names and secondary details stay aligned when the current-value marker is present.
- Empty assistant text/reasoning entries no longer leave orphaned accent lines and gaps between cards, including Copilot tool-only messages. Streaming text reveals the same retained entry without rebuilding tool cards.

- Copilot model/thinking changes no longer lose an idle/readiness transition while another configuration update is settling, preventing a queued transcript card from remaining pinned indefinitely. Configuration titles use the same Queued/Steering shimmer treatment, and truly unavailable selections report through the session notice banner instead of creating pending progress.
- Copilot reconnects fetch context usage independently of restored credit totals, without sending another message. Unavailable cold-session context remains visible as `— / —` beside cost, and late snapshots cannot overwrite newer live context or model changes.
- Copilot permission choices use the CLI’s decision variants (`approve-once`, `reject`, `user-not-available`) rather than legacy outcome values that caused real tool failures. Only explicit approval choices authorize requests; remembered grants use labelled, request-validated scopes and are never inferred.
- Copilot tool errors show their native message instead of JSON, streamed inputs update the eventual execution card, and late metadata no longer restarts or degrades completed cards.
- Bare Copilot slash commands with advertised argument choices open a searchable picker before execution, rather than relying on the SDK's default command result to request one. Explicit arguments still run directly; Escape invokes nothing. This covers `/permissions` without hardcoding a permissions menu.
- New Copilot sessions honor Copilot’s SDK-reported model/effort preferences independently at creation, omitting unset values rather than guessing defaults. Unknown values show lowercase `default model` / `default effort` before the first message; actual session values supersede creation inputs. Resume preserves saved configuration without applying current new-session defaults.
- Copilot transcript debug logs include streamed tool inputs and native permission request/completion events, correlate nested permission tool IDs, retain the reported runtime version, and safely record callbacks received before session identity is known. SDK logs remain partitioned separately from Pi and dormant ACP logs.
- Copilot SDK session snapshots, web citation offsets and the shell's self-referential command-choice initializer retain explicit types, fixing TypeScript compilation after the SDK migration and slash-command integration. The configuration snapshot reader has a distinct name from the session's public configuration interface, fixing the subsequent duplicate-member compilation failure.
- Bundled Copilot card adapters recognize the CLI’s reported `Copilot` agent identity, including the existing command-output adapter.
- Resume session sorts Pi and Copilot history together by displayed recency rather than grouping by source/catalog order. Shared session rows show the harness immediately after the date, below the title.
- ACP retains nullable tool patches and consecutive rich-content blocks, applies permission patches in wire order without overwriting newer tool updates, restores configuration controls after working turns, and drains agent output while writing large requests or stopping.
- Disabled or revoked card plugins cannot run applicability callbacks through old catalog entries while a reload is pending.

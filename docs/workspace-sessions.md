# Project windows and sidebar-first sessions

## Project identity

A project is one canonical directory associated with a window. Opening a directory is sufficient: no Git repository, manifest or registration is required. The directory is visible in the project bar and is the working directory for every session in that window.

Gitignored worktree subdirectories can live inside a project. Nesting does not group sessions launched in those directories into the parent project: distinct session working directories currently require distinct project windows. Worktree-aware grouping would require separating project identity from session working directory.

User-facing terminology is **Project** and **Project bar**. Existing `workspace` code identifiers, IPC commands, native window labels, the internal `--workspace` launch flag, and `nimrod.workspaces.v1` storage key remain unchanged; this naming change needs no migration.

## Using the project

1. Choose a directory and **Open**, or use **Open project…**. Opening a project never starts Pi. Opening a different directory creates another window; opening an already-open directory focuses its window.
2. The collapsible **Session sidebar** has one **New session** control and a flat list of open sessions with activity and close controls. It does not repeat the project directory, contain an Open sessions disclosure, or duplicate history/session actions. Arrow Up/Down and Home/End move focus between session rows; Enter/Space selects.
3. **Cmd/Ctrl+Shift+P** opens the **Command palette**. Choose **Resume session…** to get a project-scoped list that filters by name, preview and path as you type. It also exposes new temporary/demo sessions, exact-file open, and open-session navigation. Escape returns to commands, retaining the command query; Escape again closes and restores focus. Refresh retries discovery; loading, error and empty states remain visible. Closing the palette never replays an action.
4. **New session** creates a persistent Pi conversation. **New named session…** opens a compact step within the command palette: a focused single-line name field, inline **Create** button, and keyboard hint. Enter or Create starts the session; Esc closes the palette without creating anything and restores prior focus. Empty/whitespace-only names leave Create disabled. Pi's multiline extension dialogs remain separate. Pi starts with its native `--name` option; startup verifies the returned name before submission becomes available. This requires a Pi runtime supporting `--name`, with no fallback rename RPC. Naming alone does not flush an empty session to disk. **New temporary session** and **New offline demo** are explicit command-palette alternatives. Selecting a closed historical session opens/resumes it; selecting an already-open session focuses it. Use **Open session file…** for files outside the discovery location; they must belong to this project.
5. Switching sessions does not stop agents. Use **Cmd/Ctrl+Shift+[ / ]** to move through open sessions, or the command palette's **Switch session…** picker, which lists only sessions shown in the sidebar. **Resume session…** lists all resumable sessions in the project, including closed sessions. Each retains its renderer, draft, disclosures and scroll intent. Activity text/indicators distinguish working, input-needed, completed and inactive states. Pi dialogs include the originating session name and respond to that session, even in the background. Pi dialogs retain priority over an already-open palette.
6. Closing a session stops only its child; persistent history and drafts remain. Running/pending work and temporary sessions require confirmation. **Disconnect** stops the active session but leaves it visible. Closing a window stops its children; application quit stops all owned children.
7. Reopening a project restores remembered open sessions without starting Pi. Selecting one automatically loads its history and starts Pi; no prompt is submitted automatically. Temporary/unwritten sessions are not restored as live sessions; retained text is available through **Recover unattached draft…** after closing them. Recovery copies into a new session and preserves its source.

Other shortcuts: Cmd/Ctrl+T creates a session, Cmd/Ctrl+W closes the selected session, Cmd/Ctrl+B toggles the sidebar. Native platform shortcut acceptance remains separate from browser tests.

## Terminal navigation

After `mise run install-cli` (and putting `~/.local/bin` on PATH), use `nimrod .` or `nimrod /path/to/project`. The Bash wrapper opens/focuses only the project, never a session. It defaults to this checkout's built app; `NIMROD_APP` selects another copy. Restart a pre-CLI app once to enable forwarding. Native single-instance handling and the same canonical directory router used by the GUI select the existing window or create one. The CLI returns after OS launch acceptance, not confirmed focus. The installer is opt-in, refuses conflicting commands, and does not modify shell configuration.

## Native ownership and discovery

- `workspace_windows.rs` maps canonical directories to windows. Tauri injects the calling window for IPC; a frontend cannot name a different owner. Starts require that window's registered directory. Native close rejects late starts and reaps only that window's children.
- `workspaces.rs` owns one `ProcessHost` per token, scoped to its window. Independent transports retain ordered packets. Canonical session-file reservations prevent duplicate Nimrod-owned writers. Resume reserves before spawn; new sessions reserve their reported file before first save. Failed shutdown retains the reservation. Lifecycle operations serialize through the registry; sibling streams remain independent.
- `session_catalog.rs` is a read-only reader for Pi 0.86.x's cwd-scoped session directory, using its cwd encoding. `PI_CODING_AGENT_DIR` and the flat `PI_CODING_AGENT_SESSION_DIR` override are honored, including tilde/relative paths. Listing never creates directories or session files, starts Pi, loads extensions, or sends model requests. Names come from `session_info`; previews come from the first user message. Records/files use the same 16 MiB/256 MiB bounds as resume. Unreadable files are reported rather than repaired.
- Pi's `SessionManager.list` was inspected; its default-directory helper creates directories during discovery. Nimrod instead reads the known layout directly. Unrelated custom storage locations and separately encoded symlink-directory aliases are not recursively searched; exact-file open remains available. This is Pi-specific behavior, not a generic harness protocol.
- Exact-file open canonicalizes/validates before duplicate-tab lookup. Actual launch revalidates and verifies Pi's returned identity before enabling submission. Pi remains authoritative for history, configuration, model lists and conversation writes.

## Frontend state

- Each tab owns a `PiSession`, `PiTransport`, renderer root/receiver and draft selection. Selecting an inactive persisted tab starts its exact-file resume; callbacks are guarded by that tab's launch token, not by whether it is selected.
- Renderer template nodes retain `data-pi-id` hooks but get unique DOM IDs, including slash-suggestion ARIA references. Global window listeners are disposed on close. Hidden panes suspend scroll geometry observation while preserving follow intent or older-history offset; activation restores it before following new content.
- A project-local draft library (`nimrod.sessions.v1:<canonical cwd>`) is shared by tab selections. Separate windows use separate project keys, avoiding stale whole-library overwrites across projects. Legacy global drafts are copied into this namespace on first use; the source is retained. Persistent drafts are file-scoped; temporary/demo drafts are tab-scoped.
- `nimrod.tabs.v1:<canonical cwd>` retains its existing schema for open-session order and selection, despite removal of the tab strip. Existing open-session layouts migrate into Nimrod's app-managed `state.json`; draft scopes remain in webview storage. Internal `Tab` names denote session instances, not a visible tab UI. This storage contains no running processes or conversation history. Recent project paths, sidebar visibility, and the global last-session pointer also live in app-managed state. Already-mounted sidebar/session layouts aren't rebuilt from external state edits. Appearance and Runtime settings do synchronize across windows; see [settings.md](settings.md).
- Acknowledgement rules are unchanged: only a real Pi acknowledgement clears an unchanged submitted draft. Interrupted/persisted submissions become unknown, never replayed. Background acknowledgements cannot clear another tab's draft.

## Verification and boundaries

Shell tests use mocked Tauri IPC; Rust tests use disposable files and child fixtures. Real WebKit tests run independent offline demo processes and exercise switching, background completion, draft isolation, sidebar resize, bottom-follow, older-history restoration and palette modality/focus during streaming. They do not establish native Tauri window routing, picker, close/menu handling, or Windows/Linux acceptance.

The registry is not an external file lock: other Pi/Nimrod/editor processes, hard-link aliases and external mutation remain outside its guarantees. Do not resume a file still used by another process. There are no forks, deletion, archives, folders/pins, integrated diffs, generic harness adapters, or background daemon. The public theme catalog remains deferred.

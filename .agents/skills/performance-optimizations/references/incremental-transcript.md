# Make transcript updates proportional to changed content

**Status: implemented; new fixtures authored, not run. Native responsiveness acceptance pending.**

## What changed and why

The prior streaming path projected every historical row on publication, then serialized every row on paint to rediscover the changed tool. `conversation-index.ts` now owns lazy, array-identity-scoped tool locations and content-change metadata. Reducer updates locate only matching invocations, copy only the affected message/block arrays and reuse locations when identities/positions are unchanged. Structural/history replacements rebuild the index lazily; adoption remains authoritative.

`transcript-updates.ts` publishes an optional revision/base plus exact dirty rows. Tool changes carry call IDs so presentation does not enumerate sibling invocation blocks. Unchanged message/block rows are weakly cached. Authoritative `state.messages` remains a full snapshot, lazily projected from the captured immutable canonical state only when requested. It does not retain a backward chain of prior states. Metadata refers to previous-array identity tokens, not strong previous-array links.

Full and dirty-row projection share `projectToolRow` in `tool-progress.ts`, including unchanged result-processing/interruption overlays. Only full `projectToolTimeline` inserts the structural parallel-tools overview. Content updates must not remove a phase merely because progress itself did not change.

The mounted view accepts only continuous revisions, accumulates dirty rows across all events before a paint, and patches those rows without reading/projecting/serializing history or walking the tool registry. Local optimistic/receipt/queue operations, structural/progress changes, history replacement, missing metadata, revision gaps and recovery retain full reconciliation. Full fallback can still serialize rows; the normal tool-output path cannot. Ordered semantic observation remains synchronous; incremental content-only updates skip full optimistic-turn observation because they cannot introduce user/queue entries.

## Output, isolation and surrounding work

- Plain output appends to retained text nodes. Console control scanning/parsing consumes only the new suffix after append validation; ANSI appends retain existing style runs, while cursor overwrite/erase rebuilds affected lines.
- `output-source.ts` creates source tokens only at the card-render boundary; reducers and standalone envelopes carry no append bookkeeping. Prefix validation compares rendered endpoints, cached once per source pair across presentation/raw recovery; skipped intermediate cumulative chunks do not cause prefix scans. Replacements/truncations fail that comparison and replace content. Unknown sources conservatively validate their own prefix. Tokens retain shared immutable source strings, not copies or backward state chains.
- Pure presentation adapters and core fallback use their existing output/source registry to establish literal coverage without reading accumulated DOM `textContent`. Arbitrary mounted DOM plugins retain compatibility inspection even when they call `renderPresentation`: subsequent synchronous customization can invalidate the helper's source coverage. No separate coverage map or DOM mutation tracker is needed. Literal Raw output recovery appends independently and preserves its disclosure.
- Card data is still detached/deep-frozen. `immutable-snapshot.ts` copies JSON structure without cloning primitive strings, and shares only its own deeply frozen subtrees. Core snapshots tool arguments once when authoritative inputs arrive; output updates reuse them. Caller-frozen objects are not trusted merely because their root is frozen. Non-JSON compatibility values are detached rather than treated as shareable immutable trees.
- Unchanged inputs are not reserialized/replaced. Commands are processed only when their source list changes. Status/metrics/extensions/queue sections have dependency guards. Named `activityChanged`, `controlsChanged` and `composerPresentationChanged` predicates own snapshot dependencies in the shared view; local draft/recovery/lock effects still render directly. `shellPresentationChanged` in `main.ts` skips unchanged sidebar/title/bookkeeping preparation; attention and lifecycle paths remain live.
- Scroll scope is described in [affected tool outputs](tool-output-scroll-work.md). [Cards](../../features/references/transcript-cards.md), [interaction](../../features/references/transcript-interaction.md) and [plugins](../../features/references/card-plugins.md) remain canonical behavior contracts.

## Remaining costs and tradeoffs

This is not a constant-time end-to-end protocol. Pi still supplies cumulative output; framing/JSON conversion depends on accumulated output size, and each painted source pair still requires one accumulated-prefix comparison. Immutable public message arrays still require an O(message count) shallow pointer copy, and an affected assistant's block array an O(block count) shallow copy. These copies do not inspect historical payloads. Ordinary assistant text changes still inspect the affected message's blocks and reparse changed Markdown, sanitize and highlight the full growing block. Tool completion/progress/placement changes may take full reconciliation. Console rewrites/conversion from literal text to terminal controls can replay/rebuild prior content; append-only ANSI runs do not.

Custom plugins still receive full immutable card snapshots via API v2; their work is unconstrained, and custom DOM raw verification can read their output. Large-history DOM/memory and platform layout/paint/GC costs remain separate, unmeasured concerns. No public plugin API change or framework was introduced.

Existing `timeline-projection`, `snapshot-delivery`, `transcript-render` and shell probes remain. Full lazy materialization happens at its requesting boundary (typically fallback delivery/render), not necessarily inside the publication's projection probe; inclusive timing attribution must account for that. No new native report or avoided-time measurement is claimed.

## Regression risks and maintenance guardrails

- Keep canonical arrays/blocks immutable. Only content updates with unchanged locations may inherit an index; tool identity removal/replacement/start/end and history replacement must invalidate or rebuild it. New event types must choose targeted metadata or full fallback explicitly.
- Revision metadata is optional and session-local. Accumulate IDs until paint, including hidden updates; gaps force authoritative reconciliation. Do not defer or discard queue/receipt/error/identity transitions.
- Share row semantics between dirty and full projection; extend the differential lifecycle fixtures when adding phases or presentation fields. A fast path selects less work, not a second definition of the visible transcript.
- Local configuration progress joins the existing revision/paint boundary through `ConfigurationTranscript.sync`: retain operation-array identity on content-only publications and add only changed local rows for same-key updates. Insertion/unpin/removal uses structural fallback; never materialize lazy history for replacement text, persist local rows into harness arrays or introduce another scroll owner. New configuration/hidden/catch-up/browser fixtures are authored but unrun. [Model/thinking](../../features/references/model-thinking.md) owns semantics.
- Copilot metrics preserve `CopilotUsage` snapshot/control identity when reported values are unchanged. `metricsTitle` participates in the generic activity/metrics invalidation even when rounded text is unchanged; do not rebuild the metrics text node just to update its tooltip. Aggregate accounting reads follow usage/idle triggers, not text chunks, and share in-flight work. New/resume initialization supplies only seed data to that common pipeline; never copy provisional zeros into reported counters or add a separate fetch/render path. Provisional-to-reported transitions with unchanged visible text still invalidate tooltip provenance. New fixtures are authored but unrun; [SDK usage](../../features/references/copilot-sdk.md#usage-metrics) owns semantics.
- New shell/status fields need dependency guards. New presentation fields must participate in envelope/cache invalidation. Release mounted nodes on reset/removal/disposal; weak caches must not retain old output chains or leak across sessions.
- Keep append tokens at the rendering boundary, not in reducer events or envelopes. Append evidence must come from a verified rendered-source pair, never source length alone. Replacement/truncation and final output remain authoritative; control parsing, exact raw recovery and sanitization cannot be bypassed.
- Coverage metadata may replace DOM inspection only for core-owned output. Mounted plugins may mix helper/custom markup; never infer unchanged literal content merely from a retained element and remembered source.
- The ACP POC adds optional harness/native tool fields to standalone display envelopes and publishes its own continuous dirty-row revisions into the same renderer. Its adapter snapshots native tool metadata through the existing `immutableSnapshot` owner so retained inputs share identity across output-only updates. Public presentation helpers preserve the same WeakSet source-coverage optimization for in-process pure adapters; separately bundled helpers retain conservative raw inspection. Extend ACP differential/hidden cases alongside Pi before claiming shared-path regression acceptance; POC differential/session/card/shell and offline-browser fixtures pass in the full gates; no new native responsiveness measurement is claimed.
- The shared-view extraction adds an integration projection before paint. Pi's `createPiViewProjection` must preserve the lazy messages getter and stable Status-area/queue references on content-only updates; the core must not spread raw Pi state or interpret backend-specific configuration. `createPiStatusArea` and `createCopilotStatusArea` retain complete `StatusAreaSnapshot` identity and unchanged child arrays; capability changes invalidate optional surfaces. Dormant ACP publishes the same snapshot directly. The new projection/capability fixtures are authored but unrun. `test/conversation-view.test.ts` adds lazy-read/dependency and hidden-catch-up fixtures; these latest fixtures pass in the full offline gates, without a new native responsiveness claim. [Harness presentation](../../features/references/harness-presentation.md) owns the boundary/rationale.
- Markdown section `webLinks`/`baseUrl` policy participates in the same text/format render cache: policy changes must invalidate inner Markdown/URLs without replacing keyed viewports; unchanged lifecycle updates must retain DOM. Copilot web-card fixtures cover this path but are unrun; source/citation caches use immutable native object identity, not mutable caller-frozen roots. [Web cards](../../features/references/card-plugins.md#copilot-web-cards) owns behavior and evidence.
- SDK tool input/native maps are branded once at the concrete event boundary, preserving authoritative input and result identities across later metadata/lifecycle updates. Repository-result and error formatting cache only those immutable native subtrees. Input-generation rows reuse tool IDs and dirty-row publication; do not reselect/remount on late names/categories, walk history per fragment, or let late fragments replace execution inputs. New SDK observed-payload fixtures cover these paths but are unrun. [SDK cards](../../features/references/card-plugins.md#observed-sdk-tool-payloads) owns semantics.
- Only internally branded deep-frozen JSON subtrees may be shared with plugins. Do not trust arbitrary `Object.freeze`, expose mutable core arguments, or memoize mutable custom values by identity.
- Preserve tool-ID shell identity, late authoritative inputs, manual disclosure/timers, raw/final output, optimistic aliases, focus and independent scroll intent. Full fallback remains required, not an error-only afterthought.

# Customizable keybindings

**Status: implemented.** This reference owns current specifications and implementation details. [Verification status](verification.md) separates fixture evidence from native acceptance; [historical records](history/feature-records.md#keybindings) retain prior execution records.

Human guide: [Keybindings](../../../../docs/keybindings.md).

## Specification and acceptance criteria

Every palette action is bindable through one shared dispatcher; empty default bindings are valid. Recorder/reassignment/reset and file overrides preserve modal priority, explicit conflicts and existing session methods without accidental execution.

## Code map

- `src/keybindings.ts`: action IDs/labels/scopes/default arrays, persisted grammar, layout-aware recorder/matcher, conflict/reassignment planning, capture-phase dispatcher.
- `src/keybinding-editor.ts` / `src/keybindings.css`: Settings section mounted before Runtime, searchable action list, nested recorder/reset confirmation, explicit reassign checkbox, notices and focus fallback.
- `src/main.ts`: registry dispatch to existing session/palette/settings/zoom methods, effective palette shortcut labels and sidebar/settings/zoom hints. Legacy module shortcuts are disabled here so rebinding cannot leave a second hard-coded listener active.
- `src/command-palette.ts`, `src/settings.ts`, `src/zoom.ts`: independently testable default listeners remain for standalone consumers; the shell passes `shortcuts: false` / `false`. Zoom exposes `run` for dispatch without synthetic keyboard events.
- `src/preferences.ts`: grammar validation, per-action JSONC writes against a fresh native snapshot, concurrent conflict review guard, empty-object Reset all, ordered synchronization.
- `src-tauri/src/keybindings.rs`: native persisted grammar/bounds. Keep in sync with the TS validator; defaults/actions remain TypeScript-owned, not duplicated in Rust.
- `src-tauri/src/preferences.rs`: delegates keybindings validation, preserving the existing native last-valid/atomic/CAS path.
- `src-tauri/src/native_menu.rs` / `main.rs`: custom Minimize/Close Window items; Minimize restores the native macOS `Cmd+M` accelerator (menu-only on other platforms), while Close Window remains accelerator-free. Focused-window events use Tauri minimize/close, with normal window shutdown lifecycle. Quit/Open project stay native and reserved on macOS. Linux skips app-menu construction entirely (no hidden accelerator group) and exposes the replacement actions below. Open recent project has an accelerator-free native menu entry and frontend-owned configurable `primary+shift+o` default; a native accelerator would intercept the old default after rebinding.

## Linux app-menu replacement

Linux has no File/Edit/Window/Help app menu. `src/application-actions.ts` supplies registry-backed palette entries and shared execution for `open-project` (Ctrl+O), `quit` (Ctrl+Q), and unbound `minimize-window`, `toggle-maximize-window`, `close-window`, `about`. The explicit `ApplicationActionId` subset and exhaustive detail map keep native dispatch IDs and required palette descriptions typed. All are application-context/app-scope and configurable/unbindable; `actionsForWindow` gates their defaults/editor/dispatch/palette presence to Linux, keeping macOS native menus/accelerators unchanged. Overrides survive on other platforms but these Linux-only actions do not execute there. The palette's application context permits opening it from the welcome window without a project; ordinary modal guards remain.

`src-tauri/src/application_actions.rs` decodes only those explicit action IDs. Quit calls the same `request_exit` as native app Quit: all windows, draft/reference flush, deletion coordination and owned Pi/ACP/Copilot/compiler shutdown; no JS per-session teardown or direct process exit. Window actions target only the invoking window; Close uses `window.close()` and the existing Settings/reference/project close lifecycle, never `destroy()`. Open project parents the existing directory-only chooser to its invoking window; About uses a native dialog with package version/license. Project action errors use the existing application notice strip. Settings and references share the Linux app shortcuts as well as their existing Settings/Close handling; nested dialogs/recorders still block dispatch.

Menu audit: Open recent project, global/project Settings already have palette/shortcut routes; native Minimize/Maximize/Close and About gain the actions above. Editing shortcuts (Ctrl+A/C/V/X/Z, Ctrl+Shift+Z) are deliberately left to WebKitGTK, not intercepted or recreated with synthetic keystrokes/`execCommand`; removed GTK menu accelerators are not needed for native webview text editing. Actual native editing/clipboard/undo acceptance remains in [Verification](verification.md), not established by dispatch fixtures. Native titlebar controls and session-row popup menus remain; compositor blur is unrelated.

## Removed ACP actions

`new-acp` and `acp-options` are absent from the product action registry, palette,
shared dispatcher and keybinding editor. Existing settings overrides remain inert
unknown IDs, without migration or deletion. Generic ACP code remains internal;
retaining an adapter is not permission to expose its actions. `new-copilot` remains
registered, unbound by default, and labeled **New Copilot session**.

## Action contexts, data and reset semantics

Global action definitions declare an `application`, `project` or `session`
context independently of keybinding scope. Application actions can run without
a project; project actions remain available in an empty project with no selected
session. Session actions require the selected integration to contribute the same
action ID through `SessionAction`. The command palette, Status-area buttons and
shortcut dispatcher consume that capability boundary; unsupported session
actions are absent from the palette and their configured shortcuts are consumed
without execution. Temporary readiness remains a separate concrete integration
gate and must not be presented as support.

`settings.json` contains `keybindings: { [actionId]: string[] }`. No defaults are copied on startup/migration. Absence inherits defaults, `[]` intentionally unbinds, a list replaces the entire action's defaults. Multiple bindings are supported (max eight). Unknown syntactically valid IDs survive individual edits; no unknown action executes. Reset one removes its property; Reset all confirms and writes `{}` to avoid deleting comments preceding the settings property. Comments inside reset/removed overrides are naturally removed with them. Unrelated properties/comments survive.

Creation/navigation defaults: New `primary+n`, New named `primary+alt+n`, Temporary `primary+shift+n`, Switch `primary+t` only, Resume `primary+k`, Open recent project `primary+shift+o`. `primary+p` has no default. Cmd-T was removed from New rather than retained as an alias; explicit user overrides are never migrated or rewritten. Selected-session deletion remains `primary+backspace`; the repeated **Delete sessions…** picker uses `primary+shift+backspace` (`delete-sessions`, overrideable/unbindable), model `primary+shift+m`, effort `primary+shift+e`, with mode and context-window
selection registered but unbound by default. `permissions` (**Set permissions…**) is unbound and contributed by a concrete harness integration that advertises a supported permission command; it runs through that session's command owner. `cancel-configuration` (**Cancel pending configuration change**) is also unbound and contributes only while the owning configuration exposes safe withdrawal; card and palette routes share exact-key/lifecycle revalidation; multiple pending domains require an operation choice rather than cancelling an arbitrary entry; existing
palette/sidebar/session-cycle/settings/zoom keys are unchanged. Restart defaults to `primary+r`. Global Settings (`settings`) defaults to `primary+,`; Project settings (`project-settings`) to `primary+shift+,`; Edit keybindings (`keybindings`) is app-scoped with no default and opens the global window at Keybindings. These defaults do not rewrite explicit stored overrides; session/navigation palette commands generally have defaults; `select-theme`, `reload-card-plugins`, [MCP inspection](mcp-inspector.md) (`mcp`) and [performance capture](performance-diagnostics.md) (`capture-performance`) are explicitly bindable with empty default arrays. Reload rescans personal sources/refreshes the catalog for new cards without restarting Pi or rebuilding inspected cards. `demo` and `file` actions are removed from the palette, registry, dispatcher and welcome controls. Old overrides for those IDs survive as inert unknown actions; do not rewrite user settings. Action IDs intentionally align with the palette IDs.

## Invariants

- Every Nimrod command-palette command MUST have the same ID in `ACTIONS`, be configurable in Settings → Keybindings, and route through the shared dispatcher. Defaults may be empty when no shortcut is agreed; existing defaults remain overrideable/unbindable. Palette hints derive from `bindingsFor`, never hard-coded strings. New commands require default/override/unbinding regression coverage. Native-only menu actions are explicit exceptions, not a reason to omit palette actions from the registry.

- One capture-phase keyboard dispatcher in the project shell. It calls existing action methods; never sends a prompt or bypasses acknowledgement, deletion review, idle state, lifecycle guards or exact-file identity checks.
- Project bindings pause through every open modal, including native `dialog` and legacy `#dialog.open`. Reference pop-outs install the same dispatcher restricted to global Settings and Linux app actions, preserving their existing hard-coded Close behavior. Only app-scope Global Settings/Project settings/Edit keybindings/Zoom and Linux app actions work through Settings alone. The global window also permits the configured `close` action to close that native window, never a session. Nested recorders block everything. Recorder/extension/deletion/palette dialogs have priority over all bindings.
- IME (`isComposing`/229) and consumed events are ignored. Matching repeated/unavailable actions are consumed but never executed. This prevents held New/Delete shortcuts and prevents configured Cmd-Backspace from falling back to deleting draft text.
- Primary is platform-specific in real windows; empty-platform mock realms accept either Cmd or Ctrl for legacy fixtures. Explicit Cmd/Ctrl combinations remain exact. Plus/Equals share one normalized key, ignoring layout Shift; native `<` on `code: Comma` normalizes to comma for Shift-comma matching/recording (other layout characters are untouched); shifted bracket codes retain existing session-cycle behavior. If `code` is empty/`Unidentified`, Ctrl/Cmd+Shift without Alt also normalizes `{`/`}`/`<` to `[`/`]`/`,` for matching and recording. This is only a fallback for those existing punctuation forms: known different physical codes, AltGr/Alt input and plain typing are untouched; modifier matching, IME/repeat/modal/conflict guards and stored overrides still apply. Other keys normally use `event.key` (layout characters). macOS Command+Option can replace it with `Dead`/an Option-derived symbol: `optionBaseKey` falls back to `Key[A-Z]`/`Digit[0-9]` only for transformed Command+Option events, shared by matching and recording. Already-readable letters/digits remain layout-aware; no fallback applies on known non-macOS platforms or to plain Option typing. This uses standard key positions when the unmodified layout character is unavailable, not a native keyboard-layout map.
- Recorder input captures without execution and needs an explicit Save. Command+Option dead keys with a valid letter/digit code are recordable; standalone/unknown-code dead keys, IME/229 and repeated keydowns remain ignored. Escape cancels, plain Tab navigates buttons. Unsupported/native editing/menu shortcuts are rejected. Unshifted O combinations remain native/reserved except the explicit `ctrl+o` Linux default; `ctrl+q` is likewise an explicit exception. Cmd/primary O/Q forms remain reserved for macOS menus. Shift+O is permitted by both TS and Rust validators for configurable Open recent project. Plain text and Alt-only characters are not shell shortcuts; unmodified function keys are supported.
- Conflicts never silently choose a winner. UI offers explicit reassignment; manual duplicate active mappings consume the key and report an error without executing either action. Platform aliases are compared when planning reassignments.
- Reassignment is computed again against the freshly fetched native snapshot. If its affected-action patch differs from the reviewed patch or the target action changed, reject and require review. The editor also invalidates stale target editing and clears a Reassign approval when the displayed conflict list changes. Per-action edits preserve unrelated action changes; native source-text CAS handles later races without retry. Invalid external edits retain prior effective settings.
- Unrelated preference/state broadcasts do not redraw the keybinding list or disturb its focused control. Failed saves retain a visible recorder error as well as the Settings notice.
- Reset confirmations use shared `dialog-actions.ts`: eligible Reset initially has focus; Reset and Cancel have plain labels with non-visual shortcut metadata. Enter respects Cancel focus; Escape cancels; IME/repeated Enter cannot activate. Disabled/conflicted resets start on Cancel and require existing explicit Reassign. Shortcut recording retains explicit Save and no Enter shortcut metadata. Save-in-progress guards still prevent repeated commit/cancel. Unit and offline WebKit reset tests cover focus/plain labels and Enter cancellation/confirmation.
- Saving redraws rows; recorder close focuses the search instead of a detached row button, but never through a higher-priority modal. Project settings remains modal over unchanged conversation DOM; global Settings's recorder is nested in its separate app-owned window; no session start/stop is caused by preference changes.
- Native Minimize owns macOS Cmd-M, independent of project-shell modal guards; Linux uses the palette/native titlebar for window actions, while other non-macOS platforms retain menu-only Minimize. Close Window remains unbound because Cmd/Ctrl-W belongs to Close session. The custom menu items route to the focused window through Tauri minimize/close. Unshifted Cmd/Ctrl-E has no Nimrod default binding. Existing user overrides, including old model/effort shortcuts, remain valid and are never rewritten; native Cmd-M interception takes precedence over a retained override, so Reset/rebinding is needed to adopt the new model default. Native menus/text editing, OS reservations, composer delivery and reference-window Close remain outside this editor.

## Option-key regression

The original matcher compared Command+Option+N to `event.key === 'n'`, and the recorder rejected every `Dead` event. macOS Option-N may produce a dead key/tilde instead. The prior Playwright `keyboard.press('Meta+Alt+N')` supplied the literal `n` and therefore missed this shape. The new unit regression fails on the old code, then passes with the narrow Command+Option letter/digit normalization. Shell coverage uses `key: 'Dead', code: 'KeyN'` through named creation; the offline WebKit regression injects the transformed shapes and checks naming/cancellation/recording without native acceptance claims. No persisted defaults/overrides or Pi behavior change.

# Projects and sessions: implementation reference

**Status: implemented.** This reference owns current specifications and implementation details. [Verification status](verification.md) separates fixture evidence from native acceptance; [historical records](history/feature-records.md#projects-and-sessions) retain prior execution records.

## Specification and acceptance criteria

One canonical directory per window with independently owned sessions. New is persistent by default, saved identity gates submission/Restart, exact-file resume never falls back, and temporary disposal never leaks drafts into persistence.

## Project bar identity

- `index.html`: `#project-identity` groups `#project-name` and the existing muted `#workspace-label`; wordmark/spark live only in the welcome copy.
- `enterWorkspace` in `src/main.ts` derives name/parent from the native canonical cwd using `projectPathParts`, abbreviates only the parent with `abbreviateHome`, and gives the group a full-path hover title. No routing, recent-history, draft or session identity changes.
- `runtime_defaults` supplies a separate optional canonical home path from Tauri's portable path resolver; do not infer home from a project/default cwd or hard-code `/Users`. Failed home resolution leaves the parent absolute. Windows separator syntax has unit coverage, not native acceptance; Linux/native layout acceptance also remains pending.
- `src/theme.css`: identity uses `align-items:center` to vertically center the differently sized name/parent line boxes (not their baselines), and flexes into remaining space; name retains intrinsic width up to the group's width, parent shrinks first, both ellipsize. The project name is never hidden by the 480px media rule; exceptionally long names can truncate after the parent has collapsed. Roots have no parent.
- `test/project-path.test.ts`: POSIX/drive/UNC splitting and boundary-aware home abbreviation (no sibling-prefix matches). `test/shell.test.ts`: native-home fixture, identity/full-path title, root and welcome branding, no Pi launch. `test/browser/project-bar.spec.ts`: offline WebKit wide/narrow geometry, parent-first truncation, persistent name and equal name/parent vertical centers at fractional zoom. Visual/native acceptance remains user-owned.

## Product and navigation invariants

- Product cleanup: no offline-demo launch or arbitrary session-file chooser in the palette, Settings keybinding editor or welcome UI. `LaunchConfig` no longer accepts a demo flag; the app bundles only `pi-model-scope.ts`, not `demo.mjs`. Rust process smoke tests and offline WebKit keep the fixture source: the browser host intercepts only temporary-session launches and starts `demo.mjs` itself, never real Pi. Legacy `demo:` draft prefixes remain excluded from persistence/recovery for compatibility. Exact-file inspection/validation remains necessary for catalog selection and restored entries, not as a user-facing file chooser.
- Restart and Edit keybindings use the shared configurable `primary+r` and `primary+shift+,` defaults. Restart retains existing interruption confirmation, eligibility, owned shutdown and no-replay semantics; it never reloads the webview.

- Project identity is one canonical directory per window. Every session in that window has the exact same cwd; nested directories/worktrees are not automatically grouped.
- User-facing terminology is Project/Project bar. Existing `workspace` identifiers, IPC commands, `workspace-*` native labels, `--workspace` internal flag and compatibility storage keys remain unchanged.
- No Open project or command-palette buttons in the Project bar. Open project / Cmd/Ctrl+O invokes the native directory-only chooser. Open recent project uses the shared picker from configurable Cmd/Ctrl+Shift+O, an accelerator-free File-menu entry, or its palette command; command-palette entry is keyboard-only Cmd/Ctrl+Shift+P. The welcome directory chooser remains. No generic Disconnect action.
- Native File-menu Open project uses `pick_folder` and enqueues `Request::Workspace`; Open recent project requests the shared recent-project picker. It works with a pop-out focused or without a project frontend. Picker navigation's router source is absent: focus an existing project or create a project window, never rebind a mounted welcome screen. Project boot records its path in recents.
- Install a File submenu if Tauri's default lacks one (Linux). Preserve other native actions. macOS Quit MUST remain app-owned: predefined Quit invokes AppKit terminate directly and bypasses cancellable Tauri exit handling.
- Sidebar All / Unread / Working views filter the same open sessions without lifecycle effects; Switch session still reaches all open entries, switching to All for a filtered-out target. `active` is remembered navigation; `presented` owns the shown conversation/actions, and may be absent in attention. Automatic Close and successful tree deletion share connected-first cleanup selection; they may switch to All to reuse a connected session, and both load/reconnect an inactive saved fallback (deletion waits for transaction release). See [sidebar attention](sidebar-attention.md) for ordering, retention, counts, view persistence and keyboard behavior.
- **Open/closed** is sidebar membership, **connected/disconnected** is the live transport/process connection, and **working/idle** is agent activity. These are independent dimensions, not synonyms. All entries retained in the sidebar are open, including inactive restored entries, disconnected entries and temporary sessions. Hiding the sidebar or filtering rows does not alter membership. A disconnect alone must not remove an entry; closed entries must not retain owned processes. Switching entries does not stop children. Restored entries stay inactive until selected. Closing waits for observed stop before removing the entry; a failed stop leaves it visible.
- **Switch session** enumerates open sidebar entries without a connection-state requirement, even when Unread or Working filters them out. **Resume session** enumerates saved top-level project history, including already-open and closed sessions; temporary entries belong to Switch, not saved history. Do not use native process ownership or transport connectivity as the source of the open-session list.

## Recent-project picker

- `native_menu.rs` keeps Cmd/Ctrl+O on the native directory-only chooser. The accelerator-free Open recent project menu action routes to the focused project or `Popouts::focused_owner()` for a reference window, falling back to an existing non-reference window or creating a welcome window. A window-label-scoped `ProjectPickerRequests` set plus targeted `nimrod-open-project` event handles requests before frontend boot; `take_project_picker_request` consumes them once. The frontend listener targets its exact WebviewWindow (never Any); readiness gates consumption. Other modal surfaces retain priority.
- `workspace_windows.rs::list_projects` reads `Preferences::snapshot().state["nimrod.workspaces.v1"]` and canonical native `WorkspaceWindows` membership. Recent ordering is retained, duplicates/non-string entries are excluded, and otherwise-unlisted open paths append deterministically. Open means a registered project window, not session/agent state. Listing launches no Pi and performs no recursive filesystem discovery.
- `ACTIONS` registers `open-recent-project` with default `primary+shift+o`; the shell dispatcher and same-ID palette command call `palette.projects()`. Effective shortcut hints come from the registry; Settings supports override/unbinding/reset. No native Shift+O accelerator can bypass overrides. TS/Rust validators permit shifted O while retaining the native unshifted O reservation.
- `src/main.ts::paletteProjects` uses `src/project-path.ts::projectPathParts` to supply basename, `PaletteItem.projectParent`, full canonical search detail and `PaletteItem.projectOpen` to `command-palette.ts`'s projects page. The projects page reuses `.palette-selection-marker` (the same muted typographic bullet as model/thinking selection, with project-only CSS reducing its slot from 14px to 8px and its name gap from 8px to 4px); open windows show **•**, others reserve a blank slot. `.palette-project-row` renders one `.palette-item-heading` with marker, name, muted parent and an aria-hidden, non-focusable corner-down-left SVG (`.picker-enter-hint`) at the right. The SVG is an Enter-to-open hint, never a nested button. CSS keeps it `visibility:hidden` except on `[aria-selected=true]`, reserving its fixed 16px slot on every row so Arrow/filter selection never shifts text or changes parent truncation. Hover alone does not reveal it. The project marker overrides `flex-basis:8px; margin-right:-4px` against the heading's existing 8px gap, giving a 4px marker/name gap without altering the 8px name/parent gap or model/thinking marker geometry. Name width caps at 55% with ellipsis; the parent shrinks/ellipsizes first; the marker/icon do not shrink. The path splitter handles POSIX and drive/UNC shapes without changing native identity, and shows roots as the name with no fictitious parent. Multiple projects can be marked: this is membership, not `current`/`aria-current`. Accessible row labels include the full path, Open project window state and Enter to open hint; Open remains searchable without visible badge text. Search matches both name and path. `openProjectDirectory` uses `open_project_directory` → `route_workspace(app, None, cwd)`, so an existing window is focused or a new project window created, never a welcome rebind. Successful navigation updates existing recent storage; invalid paths fail without substitution or session launch. Welcome launch-form routing remains unchanged.
- Projects share command interaction dismissal, stale-result generation guards, Back and keyboard selection. The former `palette-browse` footer, option/callback and browsing state are removed: there is no native chooser within this picker. Native File Open / Cmd/Ctrl+O remains directory-only and unchanged. Empty recents direct users to File → Open project; no matches never activate anything. Click/Enter still use the accepted-action-after-close boundary, with no Pi startup or automatic retry.
- `test/project-path.test.ts` covers portable basename/parent display, root and trailing-separator cases (Windows shapes are fixtures, not native verification). `test/command-palette.test.ts` covers projects in the shared dismissal matrix, inline row order/accessibility/Enter hints, path/Open search, absent chooser/empty-state guidance, stale discovery and accepted Enter. `test/shell.test.ts` covers boot-pending/targeted native requests, parent display and navigation without native dialog calls or Pi startup. Rust tests retain recent ordering/dedup/native membership. `test/browser/projects.spec.ts` exercises one-line geometry, muted parents, selected-only Enter icons with no geometry change, compact 8px dot/4px name spacing, unchanged name/parent gap and truncation at normal/narrow widths under fractional zoom, retaining the draft and offline child. Native visual/menu/focus, pop-out ownership and Linux/possible Windows acceptance remain user validation, not fixture inference.

### Known UX gap: recent directories versus session history

- The picker is directory-navigation history, not a catalog of directories containing Pi sessions. Any previously opened directory—including the home directory—can appear even with no remembered open sessions or saved history. Do not infer why a particular path was recorded without inspecting its provenance; the current recent-path schema does not retain that provenance.
- The **•** marker means a registered project window exists, not the current project or an indication of saved sessions. Selecting the row performs navigation. Opening a recent directory restores remembered sidebar entries without starting Pi; an empty sidebar does not prove there is no closed history. Resume session is the explicit project-scoped history lookup.
- User testing exposed two clarity gaps: Open badges were mistaken for buttons (now replaced by the shared model/thinking bullet marker), and opening an incidental directory can look like an unexpectedly blank project. There is currently no **Remove from recent projects** control, so stale/accidentally opened directories cannot be removed through the UI.
- Follow-up UX work (not implemented): add Remove from recent projects that removes only navigation history, never files, sessions, drafts or an open window; review empty-project copy so **No open sessions** is distinct from **No saved sessions**. Do not silently filter out home/non-repository/empty directories: any directory remains a valid project.

## Session management

### Selection after Close or successful deletion

Close and definitive batched deletion use [SessionNavigation replacement and connection contracts](session-navigation.md#contracts). This is the canonical policy; don't implement another recency/replacement algorithm here.

The shell applies the navigation plan through `activate`, retaining mounted renderer, draft, reading position, modal priority and pop-out synchronization. Every visible activation requests connection through `SessionConnection`; deletion only signals barrier changes. Inactive saved replacements connect after authoritative barriers release, never replaying navigation effects or prompts. Quarantine/lifecycle guards remain authoritative.

### Shared session row presentation

- Switch uses the navigation model's canonical All order independently of filters; Resume retains history catalog order. Both pickers carry `PaletteItem.sessionRow`. The sidebar, Switch and already-open Resume entries use the same shell `sessionRow(tab)` result (`tab.lastUsed` and `indicator(tab)`). `src/session-sidebar.ts` owns shared DOM creation, incremental updates, time formatting, optional open membership and accessible status labels; all three surfaces use the same row/indicator/heading CSS.
- Visible content is an indicator, title and muted relative time/date; Resume, Switch and Delete sessions append the shared selected-only Enter SVG inside `.session-row-heading`, aligning its fixed 16px slot with the title rather than the whole title/timestamp row, matching Select theme. Keep the timestamp outside that heading; selection uses visibility rather than removing the SVG to preserve truncation geometry. Palette-only `.session-row` uses `box-sizing:border-box` and the same `9px 10px` padding as other palette options: inherited `width:100%` otherwise adds padding outside the list width and clips the Enter SVG's right bend. Keep sidebar row geometry unchanged. Regression tests must compare the SVG's right edge with the list's clipping viewport, not just its own dimensions; account for CSS zoom when mixing client widths with bounding rectangles. `test/browser/picker-enter-icon.spec.ts` compares theme/session icon dimensions, path, stroke, title alignment and selection geometry at wide/narrow widths. Closed history uses a dash (`state: closed`, `label: Closed`, `mark: —`), distinct from open-but-inactive hollow circles, and the maximum identity-bound remembered recency/latest saved user-message timestamp, never mtime. Missing time shows No message time. Resume catalog ordering remains unchanged (descending modified time); this change unifies presentation, not discovery or ordering.
- Status, Current, history previews and paths remain searchable, without separate visible status/preview lines or hover tooltips. Other palette pages retain their existing renderer.
- `test/command-palette.test.ts` covers every indicator state, timestamp semantics, accessible labels and status search; `test/shell.test.ts` compares Switch/sidebar content for connected/inactive entries hidden by a filter, preserving membership and process reuse.

### Resume picker

- `session_catalog.rs` returns optional `parentSession` metadata from Pi's header; `sessions.rs` carries the same metadata through exact-file inspection/startup. Missing/null parent means root; a nonempty string means child. Malformed parent metadata is reported, not treated as a root.
- `paletteSessions` filters children after overlaying open-session titles. Pi's subagent extension uses `parentSession`, as do saved forks/branches: the picker intentionally lists roots, not all user-created branches. Do not infer child status from names, prompts, filenames, notifications or agent tool calls in a parent's history. Children written without parent metadata cannot be reliably distinguished.
- Open exact-file entries outside the catalog are inspected read-only before inclusion, so an open child cannot leak back into Resume through sidebar merging. Failed inspection retains the sidebar entry/draft and contributes a picker warning; it does not launch Pi. Such entries have no catalog mtime and sort after catalog history. Their row time comes from the open entry's recency, not inspection/resume time.
- `SessionRowPresentation.open` carries sidebar path membership only, not `presented`, transport, child ownership or the current sidebar filter. It adds Open to search and the accessible name without a visible badge. Closed rows carry the distinct dash indicator; open rows reuse sidebar activity (including inactive circles). `src/picker-hints.ts::createPickerEnterHint(document)` owns the single Enter SVG definition for Resume, Switch, Delete sessions, recent projects and theme previews. `.picker-enter-hint` in `src/workspace.css` owns its shared 16px dimensions, non-shrinking slot and muted color; palette-specific rules own right alignment and selected-only visibility, so selection does not change truncation. New picker surfaces should reuse this factory/class rather than copy paths or styles. Confirmation action buttons remain plain labels, and model/thinking pickers retain their existing no-icon presentation. `test/picker-hints.test.ts` covers owning-document and decorative/non-focusable semantics. It is aria-hidden/non-focusable, never a separate button. Previews and file paths are search-only.
- Choosing an open entry goes through the existing `openSession`/activation path: reuse its mounted entry and connected process, or explicitly resume an inactive entry. Switch remains all open entries (including child and temporary sessions). Closed children have no product opening entry point. No duplicate entry/process or prompt replay.
- Fixture coverage: `test/command-palette.test.ts` checks membership/search/activation and Enter hint structure/keyboard selection; `test/shell.test.ts` checks connected/inactive/disconnected membership, filtered rows, Close, root/child filtering, out-of-catalog open children and unchanged Switch/reuse behavior. Rust catalog fixtures cover absent/null/valid/malformed lineage and child exact-file inspection. Offline WebKit also compares Resume/Switch geometry and timestamp typography, verifies long-title truncation and search-only previews.

### Reload (Restart session) lifecycle

The user-facing action is **Restart session**; “reload” refers to its Project bar icon, not Pi's `/reload` command or a webview reload. See the [user guide](../../../../docs/sessions.md#restart-session).

`restartable(tab)` requires a verified `file.exists`, non-temporary mode. `restartControl()` also disables the icon before boot or while starting, closing or restarting. Keep it visible when disabled and supply reason-specific tooltips. Newly reported file paths are not persistence: native `session_file_info` must confirm identity/cwd and existence before enabling.

`restartSession(tab)`:

1. Revalidate session presence, saved identity, settings modality and lifecycle guards. Capture the target session, not an active-session pointer across awaits.
2. Set `restarting` before any confirmation/stop await. This disables duplicate restarts/Close, marks the row Restarting, blocks automatic launch on reselection, and locks session input. Stop confirmation is needed for busy/compacting state, submission state, extension input, or pending queue work. Cancel is a no-op except clearing the guard.
3. Call `stopOwned` for its exact token. This is native IPC, NOT an RPC abort/get_state request, so a stuck RPC does not prevent termination. Do not start a replacement until native stop resolves. Preserve file reservations on native failure.
4. Cancel preference/extension dialogs, settle pending submissions through `sessionDisconnected`, disconnect the old transport and mark it ended. Suppress generic disconnected notices while restarting.
5. Reuse `launch` with exact saved file/ID, runtime's next-launch preferences and a new token. Native launch revalidates disk identity/cwd; Pi's identity must match before submission is enabled. No fresh-session fallback.
6. Preserve mounted session ID, sidebar row, renderer root and draft identity. Reuse the normal explicit sessionReset/history path: disclosure state resets; this is not a webview reload. Pop-out ownership remains attached to the same mounted session and saved identity. Do not retire/close the source session.
7. Clear the restart guard in finally. The pane stays inert through restart startup, so the ordinary launch focus is deferred until the restart lock is cleared; focus the composer only if that session is still selected, startup succeeded and no dialog is open. Errors retain the entry/draft, with explicit retry. A stopped child with invalid history remains inactive; no automatic resend.

`stopOwned` coalesces concurrent cleanup requests for a token. Clear only the matching cached promise on rejection so another explicit attempt can actually retry stop. Keep successful stops cached until `launch` allocates a new token, preventing delayed old cleanup from stopping the new child.

No automatic prompt or queue replay. Renderer `sessionDisconnected` turns pending submissions into unknown; only actual Pi acknowledgement may clear an unchanged submitted draft. Newer drafts remain. Token/generation guards reject old channel events, late receipts, identity callbacks and startup failures after another launch. Sibling transport/drafts/processes remain independent.

Do not call `clear_queue` before restart: that would require a responsive Pi and defeat the escape hatch. Existing locally retained recovery text survives; remote in-flight/queue state is not a process-continuity guarantee.

### Delete session trees

The Project bar's trash icon, per-row sidebar trash and palette action use Nimrod's Rust-native session-file preview/removal with confirmation scoped to the initiating window. App-wide locks coordinate affected session writers, and persisted quarantine prevents implicit resume after partial/unknown outcomes. This changes neither Close nor Restart semantics; see the [session deletion reference](session-deletion.md) for code, protocol, lifecycle and fixtures.

## Saved identity and history acceptance

New saved launch omits `--no-session`; temporary launch is explicit and independent of absent metadata. New named sessions pass literal native `--name`, never a fallback rename RPC/retry. Failure remains a startup error.

Resume passes a canonical absolute `--session` file, never `-c`, partial ID or latest lookup. Headers v1–3 are supported within 256 MiB/file and 16 MiB/record bounds. Remembered session ID is checked before launch to detect replaced files; Pi's returned `get_state` path/ID/cwd must match before enabling submission. Failure never substitutes a new session.

A reported path isn't proof of persistence. Pi 0.86.1 was observed delaying an empty/rename-only save until assistant content existed. Keep the awaiting-first-save badge and provisional draft identity until native inspection confirms matching file/ID/cwd. Coalesced metadata refresh after completion discovers first write without polling and promotes drafts/pop-outs, including background sessions.

History `get_messages` response applies synchronously before later channel events; it is Pi's active context, not every stored branch. Routine snapshots preserve live presentation; explicit launch/resume resets at its existing boundary. See [transport/acknowledgement](pi-transport.md) for canonical ordering and receipt contracts.

## Ownership, discovery and persistence

- `WorkspaceHost` owns one `ProcessHost` per token scoped to the native calling window. Frontends cannot stop another window's child. Canonical session-file reservations prevent duplicate Nimrod writers, not external writers or hard-link aliases.
- Native start/stop serialize registry/child slot access. Stop waits for child exit; Unix escalates SIGTERM to SIGKILL after 1.5 seconds, Windows uses native termination. Target only owned children; no OS-wide process scans or daemon claims.
- Resume uses canonical absolute `--session` paths, never `-c`, partial IDs or most-recent lookup. Inspect rejects missing/empty/malformed/unsupported files and wrong cwd; 256 MiB per file, 16 MiB per JSONL record. Pi interprets/migrates history.
- `session_catalog.rs` reads Pi's encoded cwd directory, or `PI_CODING_AGENT_SESSION_DIR`; `PI_CODING_AGENT_DIR` also applies. Expand tilde/relative paths consistently with child environment. Listing must not create files/directories, load extensions, launch Pi or send prompts. Pi's `SessionManager.list` creates directories during discovery, so do not substitute it for Nimrod's read-only reader.
- Resume and Delete sessions share `paletteSessions` → `list_workspace_sessions` → `session_catalog::list`; do not add a view-specific reader or cache. Catalog discovery reads the first header, scans forward only until the first nonempty user preview, then scans backward in 64 KiB chunks for the latest `session_info` and latest user record with a usable timestamp. Stop when both are found; unnamed/no-user histories may require scanning the body to the header. Unrelated records are scanned as bytes rather than deserialized; literal enum markers (plus Unicode-escape fallback) select records for JSON parsing. Memory is bounded to one 16 MiB record plus reader buffers. Name-clearing records win over older names. Latest user record order wins over clock skew; invalid/missing timestamps fall back to an earlier usable time. Catalog ordering remains mtime-based and preview/path search is unchanged.
- Catalog listing is metadata extraction, not full JSONL validation: malformed skipped middle records need not generate warnings. Bad headers, parsed metadata and encountered oversize records still do. Exact-file `sessions::inspect` and deletion fingerprint/validation continue fully validating the affected history before launch/removal; no acknowledgement is inferred from metadata. `sessions::inspect` retains its existing maximum-user-timestamp behavior for exact-file recency rather than becoming a second catalog reader.
- Fixture coverage in `session_catalog.rs` asserts early tail termination with counted I/O, forward preview, unnamed/cleared names, invalid times, backwards clocks, escaped enums, fake payload markers, UTF-8/CRLF/blank lines/chunk-spanning records, record bounds and malformed middle history still rejected by exact-file inspection. Shell tests assert both views use identical native catalog/presentation without starting Pi.
- Custom unrelated paths and differently encoded symlink aliases are not recursively searched; there is no product arbitrary-file opening path. Existing remembered entries still validate their exact identity. Names come from `session_info`, previews from first user message; unreadable files are reported, not repaired.
- Project draft library: browser storage `nimrod.sessions.v1:<canonical cwd>`. Each session forks shared backing metadata with its own selected draft key. Persistent drafts use `file:<canonical path>`; new persistent sessions use `unassigned:<mounted UUID>` until verified promotion. Temporary drafts use their project/mounted UUID namespace only in memory. Legacy `demo:` prefixes remain disposable. `SessionDrafts.flush` excludes both prefixes even during sibling saved-session writes; `recoverable` excludes them. Loading ignores older persisted entries, and the next library flush removes those old entries from the serialized library.
- App-managed `state.json` retains `nimrod.tabs.v1:<cwd>` for open order/selection and per-entry `lastUsed` timestamps (All displays recency order; ties retain open order), `nimrod.recency.v1:<cwd>` for canonical-path/session-ID-bound recency across Close (creation/accepted message time, historical user-message seed for unknown sessions), `nimrod.workspaces.v1` for recent paths, `nimrod.sidebar.visible`, `nimrod.sidebar.width:<cwd>` for independently saved sidebar size, `nimrod.last-session.v1` and legacy launch state. Naming cleanup needs no schema migration. Already-mounted layouts are not rebuilt from external state changes. Runtime/theme/zoom synchronize separately through Preferences.
- Closing a saved session is not deletion. Unwritten persistent-session drafts remain explicitly recoverable; recovery copies rather than consuming them. Temporary sessions are disposable: confirmation states that drafts, queued messages and pop-outs are discarded. `Dialogs.confirm` focuses its action and uses plain labels with non-visual shortcut metadata; Close/Restart supply action-specific labels while Pi keeps Confirm. Enter honors Cancel focus, otherwise confirms; Esc cancels. Shared `dialog-actions.ts` suppresses composing/keyCode-229/repeated Enter. Its per-request keyboard listener is removed on close; input/select dialogs keep their existing behavior. Wait for owned shutdown before detaching; Cancel or failed stop retains the live session/draft. `detachTab` disposes the view and calls `discardTemporary`, which deletes runtime memory and blocks late writes from resurrecting it. No temporary state survives window close, quit or reload. Existing native pop-out synchronization releases temporary runtime windows without writing saved references. `persistTabs` explicitly excludes temporary owners. Browser storage errors are visible and are not a durable-draft guarantee.

## Rendering, focus and related features

- Each mounted session owns its controller, transport, renderer and draft selection. Preserve DOM when switching; suspend hidden geometry observations and restore reader intent when selecting.
- Modal palettes/dialogs own focus during background streaming. Escape cancels/closes the entire command interaction and restores prior focus; explicit Back returns to commands with the prior query. The [command-interaction reference](command-interactions.md) owns the shared lifecycle contract. Lifecycle actions run after native HTML dialog close. Guard IME/repeated Enter.
- Restart uses an explicit launch boundary, so do not infer ordinary snapshot preservation of disclosures. No document/window reload and no geometry reset for other sessions.
- Pop-out sync is at selection, identity promotion, close and boot boundaries. Restart keeps runtime owner identity; see [pop-outs](pop-outs.md) before changing source-session retirement/focus behavior.
- Native menu, folder chooser, AppKit focus, menu shortcuts and Windows/Linux behavior require native acceptance. Source guards/jsdom/offline WebKit are not proof of native execution.

## Presentation contract

- Single self-contained browser source with type-only SDK import; no runtime dependencies/resource loaders, filesystem/network operations or agent actions. Uses only owner document/slots, managed events/mutation, safe Markdown, output registration and presentation Copy/Open/Pop out.
- Summary labels are human-readable; previews show first request target and additional count. Argument parsing accepts structured/complete JSON and complete top-level strings in partial generation fragments, never nested/incomplete guesses. Request options are explicit requested values; do not infer actual provider selection. Proxy/auth credentials are omitted from custom summary/body; core Raw inputs is untouched.
- During generation/execution, only the existing generic text-section helper is mounted, with stable plain live output. Rich request/source/reference/Markdown layout stays detached until execution finishes; no hidden registered source viewport or duplicate raw-output disclosure participates in streaming layout. The compact live layout remains a presentation choice, not the fix for the empty region; overflow containment below owns the reproduced cause.
- Returned text uses safe Markdown, except explicit raw fetch mode uses literal preformatted text. Its scrollport is `position: relative`, establishing the containing block for absolutely positioned Markdown/code accessibility nodes. Without this, `.code-copy-status` used the outer relative `.tool-card` as its containing block and escaped the inner overflow clip, inflating ancestor scrollHeight despite remaining visually hidden. Relative links resolve only against one known HTTP(S) fetch target; absent/ambiguous base leaves them inert. Web links are HTTP(S), contain no credentials/control/whitespace and use native validated handoff exactly once; never navigate the webview or preload content.
- Sources are conservatively recognized numbered-title/next-line-URL pairs or stored-result headings from retained text; query grouping is preserved. They are links mentioned, not validated source metadata or authoritative totals. A truncation-marker tail URI is excluded. Maximum 200 source cards/32 response-ID controls with visible notices, while full retained text remains accessible.
- Source nodes/handlers are keyed and retained across updates; pruned/disposed controls release handlers. Source and returned-content viewports are independently registered so host caps/inspection apply. Changed Markdown replaces its inner nodes; no claim of preserving focused inner Markdown controls across changed text.
- Copy actions snapshot exact current returned text/URL/ID. Pop out requests Markdown or raw text according to available mode. Managed handlers prevent duplicate pending actions, use aria-busy instead of disabling focused pending controls, catch expected operation failures and ignore completion after signal abort. No replay, provider call, automatic fetch, next-page execution, curator launch or Pi state mutation.
- SDK result metadata/non-text blocks remain unavailable; no invented progress, total counts, media or provider routing. Stored raw-mode content cannot always be identified; exact Copy/Raw output preserves it. Upstream format changes fail conservatively to readable text/raw rather than throwing or guessing.

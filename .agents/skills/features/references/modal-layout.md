# Shared modal layout and command rows

**Status: implemented.** This reference owns current specifications and implementation details. [Verification status](verification.md) separates fixture evidence from native acceptance; [historical records](history/feature-records.md#modal-layout) retain prior execution records.

## Specification and acceptance criteria

Ordinary dialogs share a shell, not identical content. Confirmation labels remain plain, arrow keys navigate enabled footer actions, Enter follows focused action/Cancel, Escape cancels, and loading review retains Cancel focus after late population.

## Contract and code map

- `src/modal.css` is the sole ordinary-modal shell authority: `.nimrod-modal`, `--modal-*` geometry/spacing/backdrop tokens, `.modal-stack`, `.modal-header`, `.modal-title`, `.modal-description`, `.modal-body`, `.modal-actions` and `.modal-overlay`.
- `index.html` applies it to command palette, host input/select/confirm and deletion review. `src/keybinding-editor.ts` applies it to the dynamically created recorder. `src/pi/resume-modal.ts` applies it to the retained renderer picker. `src/pi/transcript.html` applies it to Pi's editor card/overlay.
- `src/main.ts` imports the shared stylesheet after content styles. Offline browser/view fixtures must also include it; esbuild fixtures discard CSS imports.
- No ordinary modal-specific selector may redefine shell width, position, padding, border, radius, surface, shadow or backdrop. Named-session and deletion-review width overrides were removed. Settings remains the explicit full-window exception in `src/theme.css`; native file choosers are not app modals.
- Whole-window translucency uses a shared denser glass panel, restrained endpoint-continuous scrim, and scoped field/inset surfaces. Opaque/Reduce Transparency preserve the original solid appearance. [Translucency](translucency.md#shared-modal-glass) owns density/contrast calibration, nested [modal depth blur](translucency.md#modal-depth-blur-and-renderer-parity) and button tint credit; `.nimrod-modal` consumes those values here. No per-dialog glass or blur overrides.
- Native `<dialog>` and the existing Pi editor overlay share presentation, not lifecycle. Do not change native modality, acknowledgement, Escape/Back, request correlation, editor responses or focus restoration as part of styling. The editor remains the existing non-native overlay; this work does not claim improved modality/accessibility.
- Override the native dialog UA `max-width` cap in the shared shell; otherwise native dialogs and overlay cards differ by a few pixels at zoom/narrow widths.
- Scrollable bodies shrink within stack/form height limits; footer actions stay outside content scrolling. Shell overflow remains available for unusually long non-body content.

## Implementation checklist

Apply this to every new or modified ordinary modal, including previews and dynamically created dialogs:

1. **Reuse the existing interaction first.** Host input/select/confirmation dialogs use `Dialogs`; command-palette pickers use its existing page lifecycle rather than a new dialog. Their shared presentation already uses the helpers below.
2. **Use the shared shell.** Apply `.nimrod-modal` and the appropriate `.modal-*` structure from `src/modal.css`. Do not duplicate shell geometry, theme surfaces, animation styles, duration calculations or reduced-motion handling in feature code.
3. **Use the lifecycle helpers, not raw DOM mutations.** Import `showModal(dialog)` and `closeModal(dialog, result?)` from `src/modal-motion.ts` for every programmatic open/close path. The retained Pi editor overlay uses `showModalOverlay(overlay)` / `closeModalOverlay(overlay)` instead of manually adding/removing its `open` class. Do not call native `.showModal()` / `.close()` directly in ordinary modal feature code, including cancel, error and teardown paths. The CSS class alone is insufficient: helpers supply the CRT/Hologram beams, pre-close capture and stale-motion cleanup.
4. **Keep native defaults centralized.** Native `method=dialog` forms and Escape/cancel are supported by the shared controller; do not add per-modal animation listeners or duplicate request settlement. `showModal` installs the document controller lazily; a new standalone window/entry point must ensure that controller exists before native dismissal and dispose it with its window owner. Project/global Settings already own this installation. The [motion contract](#modal-motion) owns default-action timing and deduplication.
5. **Never gate semantics on animation.** Preserve the feature's validation, return values, request correlation and focus restoration. Do not await an animation or add a close delay before settling an action. Decorative snapshots must remain inert and cannot become a second interaction owner.
6. **Extend the relevant fixtures.** Cover controlled/programmatic close plus native form/Escape paths used by the feature, focus/parent-modal preservation, reopening during exit, and None/reduced motion. For browser default-action regressions, use trusted Playwright clicks/keys—not only `element.click()` inside `page.evaluate`, which can mask microtask/default-action ordering. Follow repository authorization rules before running validation.

**Exceptions:** full-window Project settings uses `installSettings` in `src/settings.ts`, not ordinary modal animation; it clears decorative remnants on navigation. Global Settings is a native window containing that page. Native OS file/directory choosers keep their platform lifecycle. These exceptions are not precedent for bypassing helpers in new ordinary dialogs.

## Modal motion

- `src/modal-animation.ts` owns global preference decoding/root presentation tokens; `modal-animation-defaults.ts` owns defaults and bounds. `src/modal-motion.ts` owns native/overlay presentation, scan layers and lifetimes. `src/modal-scan.ts` is the pure absolute-pixel edge planner/sampler. `src/modal.css` owns the Subtle entrance and scrims, **not a second scan animation clock**. Full-window Settings, native windows/choosers and transcript disclosures remain outside ordinary-modal motion.
- Global Appearance offers **None / Subtle (default) / CRT power-on / Hologram** with one contextual slider and **Preview animation**. Subtle shows **Duration (milliseconds)**, 100–1500 in 10 ms steps, default 500. CRT/Hologram show **Scan speed (pixels/second)**, 100–1500 in 50 px/s steps; absent speed defaults to CRT 500 / Hologram 1000. Larger speed means faster motion. Controls use [shared range inputs](settings-layout.md#range-inputs), update readout/fill immediately and commit on native change/release, never per drag frame. Pending saves/external snapshots cannot overwrite newer edits.
- JSONC keys: `appearance.modalAnimation` (`none | subtle | crt | hologram`), `appearance.modalAnimationDuration` (Subtle milliseconds) and `appearance.modalScanSpeed` (CSS px/s). Duration and speed are independent remembered overrides; explicit speed is shared between scan styles. Changing styles changes units/defaults immediately without confusing in-flight edits. Existing duration keys are retained for Subtle, **never converted or interpreted as px/s**; no startup migration/rewrite. Legacy duration file values remain decodable at integer 0–2000 and normalize to the 100–1500/10 ms grid. New speed files validate integer 100–1500 in TS/Rust and normalize to the 50 px/s grid. Both keys are global-only and use existing JSONC/CAS synchronization; project overrides reject them.
- Subtle retains its fade, 4px lift and 98% scale; dismissal remains 75% of configured duration. CRT reveals outward from its initial center with two theme-accent 2px edges; Hologram reveals downward with a 2px line and 16px/25%-opacity trail. Scan panels do not fade or tint. The theme's focus/progress fallback supplies `--modal-beam-accent`. No loop, flicker, content scaling or bright-panel flash.
- Scan time is **remaining travel distance / CSS px per second**, without reference-size scaling or a duration cap. CRT initially travels half the box height per edge; Hologram travels the full height. Closing uses speed × 1.25 (20% less time for the same distance), sampled from the captured current reveal rather than assuming entrance finished. Closing works on a frozen inert copy, not the live picker. Scrims fade independently in up to 150 ms and do not affect line speed.
- Opening uses a scoped ResizeObserver, never per-frame DOM polling. On size change, sample the old segment's current absolute edge positions from its animation clock, cancel that segment, and retarget from those positions with the same speed. A completed edge stops while another continues; no backward motion or normalized-height jumps. Extra keyframes handle asymmetric CRT boundaries. Hologram shrinking past the scan finishes immediately; a CRT box already revealed or moved entirely outside its old reveal band finishes instead of concealing filtered results. Growth extends remaining travel. Before first paint, preparation may follow the new box; once visible, positions are preserved. Width/zoom geometry follows the current measured box.
- Panel/beam keyframes start together on one document-timeline timestamp. Initial preparation is held at frame zero until a single animation frame; resize retargeting starts immediately from the sampled position, not with an extra frame pause. Segment revisions prevent rejected completion promises from a retired segment removing its successor. Completion/cleanup never closes a real dialog or runs its accepted action.
- All native/overlay programmatic paths use shared `showModal` / `closeModal` / overlay helpers. Real native close/class removal, return values, request settlement and focus restoration stay **synchronous**, never animation-gated. A show canceled before scan setup does not flash an exit copy. Native form/Escape capture survives to the actual queued `close` event, respects preventDefault and deduplicates controlled closure. A zero-delay cleanup releases prevented/still-open captures after default processing; it is not a visual completion timer. No prototype patch or request replay.
- Decorative layers are inert, aria-hidden and pointer-transparent. A manual non-modal popover retains top-layer presentation without native CSS overlay/discrete-transition support; older engines portal into the remaining parent dialog/body. Snapshots rewrite IDs to scoped data attributes, freeze theme/typography, copy live field/scroll values, and omit autofocus/handlers/scripts/frames/live notices. Real document queries do not see duplicate interactive controls. Capture/animation failure cannot prevent native close.
- None and reduced motion disable effects; hidden documents create no effects. New modal opens, relevant preference changes, reduced-motion/visibility changes, resize/pagehide and disposal retire old layers and cancel start frames/observers. Actual finished/canceled promises determine completion—no wall-clock cutoff. Global Settings owns installation/disposal; other windows use the lazy shared helpers.
- **Authored, unrun coverage:** `test/modal-scan.test.ts` (size/time, equal px/s after grow/shrink, CRT asymmetric stops, partial closing), `test/modal-motion.test.ts` (shared starts, retarget/cancellation generation, inert isolated snapshots, native defaults/focus, overlay/None/visibility/cleanup), preferences/native fixtures (separate validated global keys), and offline browser modal animation/CRT/Hologram/preview tests (units, values, actual pixel travel, filtering while usable, default Close/Escape and preserved drafts).
- Native acceptance remains pending for scan speed across sizes, live filtering/growth, keyboard/focus, CSS/native zoom alignment and all themes/platforms. Earlier user feedback accepted actual-app Subtle closing and slider accent initialization, not this new scan-speed implementation. No build/app launch or native/platform acceptance is implied by source fixtures.

## Confirmation actions

`src/dialog-actions.ts` shares plain action labels and non-visual `aria-keyshortcuts`. Buttons contain label text only; no Enter SVG, Esc text or hint-specific styling. Picker-row hints are unchanged. `Dialogs.confirm` accepts an optional action label after owner; shell Close/Restart provide explicit labels, Pi retains Confirm. Input/select calls clear shortcut metadata and reset the generic label.

`navigateDialogActions` shares footer-button navigation across host input/select/confirm dialogs, deletion review, keybinding recorder/reset dialogs and Pi's editor overlay. Unmodified Left/Up move backward and Right/Down move forward in DOM order, wrapping between enabled, non-hidden/non-inert Cancel and accept buttons. Navigation changes focus only, with no activation or scrolling; disabled Delete is skipped during loading. Repeated arrows can move focus; composing/keyCode-229 arrows are consumed without movement. Arrows from text fields, selects, the shortcut-recording input and other content retain their existing behavior; modified arrows are untouched. Palette pickers retain their existing list navigation (they have no Cancel/accept footer pair).

Host confirmations, populated deletion reviews and eligible keybinding resets focus the confirmation action. Enter honors Cancel focus (including descendant nodes), otherwise activates the enabled confirmation; Escape cancels. Repeated/composing/keyCode-229 Enter is consumed without activation. Native form return values/request correlation and close-time focus restoration remain unchanged. Key recording still captures shortcuts rather than treating Enter as Save. During async reset saving the existing click guards prevent duplicate save/cancel.

Deletion loading disables Delete, clears its Enter shortcut metadata and focuses Cancel. A visible loading-to-review transition preserves focus rather than moving it after the user has begun interacting; Enter on Cancel cancels both loading and populated review. Fresh ready-only reviews focus Delete. See session-deletion reference.

Unit fixtures cover all four arrow directions/wrapping, reversed DOM order, disabled/hidden/inert actions, modifiers, IME/repeats, editing controls, default/Cancel focus, plain labels/shortcut metadata and cleanup before input. Offline WebKit fixtures cover arrow navigation followed by Enter in temporary Close, deletion review and keybinding reset dialogs, default focus, absence of button hints, close restoration and retained drafts. The arrow-navigation additions have not been executed yet. Native visual acceptance and Linux verification remain pending.

Copilot denial feedback and custom question answers use the existing host input dialog layered above their retained Permission picker or Question picker; the parent does not change size to become a text editor. Questions use **Enter your own answer…** and **Submit answer**, with cancellation returning to the unchanged picker without answering; [Copilot questions](copilot-sdk.md#questions-and-custom-answers) owns lifecycle. `Dialogs.input` accepts an optional submit label (default **Confirm**, permissions use **Send denial**). Shared shell geometry, native topmost focus and input Enter/newline behavior remain authoritative; no feature-specific width/position or motion override is introduced; the shared modal motion applies. Cancellation/disposal revalidates the concrete permission owner before applying text. New retained-palette/permission unit, shell and offline-browser fixtures are authored unrun; native stacking/zoom/accessibility acceptance remains pending.

## Command rows

`PaletteOptions.commands()` requires a `detail` string; picker items retain optional metadata. Every shell command supplies a short explanatory description in `src/main.ts`, rather than a project path/current value/session title. `src/command-palette.ts` appends the effective-binding `<kbd>` inside `.palette-item-heading`, after the flexible title, and the `.palette-item-description` below it. Unbound commands have no shortcut placeholder. Both fields stay visually secondary on selected rows. Picker-specific rows/order and MRU behavior remain unchanged. Descriptions participate in existing text filtering.

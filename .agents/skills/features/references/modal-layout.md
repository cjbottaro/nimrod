# Shared modal layout and command rows

**Status: implemented.** This reference owns current specifications and implementation details. [Verification status](verification.md) separates fixture evidence from native acceptance; [historical records](history/feature-records.md#modal-layout) retain prior execution records.

## Specification and acceptance criteria

Ordinary dialogs share a shell, not identical content. Confirmation labels remain plain, arrow keys navigate enabled footer actions, Enter follows focused action/Cancel, Escape cancels, and loading review retains Cancel focus after late population.

## Contract and code map

- `src/modal.css` is the sole ordinary-modal shell authority: `.nimrod-modal`, `--modal-*` geometry/spacing/backdrop tokens, `.modal-stack`, `.modal-header`, `.modal-title`, `.modal-description`, `.modal-body`, `.modal-actions` and `.modal-overlay`.
- `index.html` applies it to command palette, host input/select/confirm and deletion review. `src/keybinding-editor.ts` applies it to the dynamically created recorder. `src/pi/resume-modal.ts` applies it to the retained renderer picker. `src/pi/transcript.html` applies it to Pi's editor card/overlay.
- `src/main.ts` imports the shared stylesheet after content styles. Offline browser/view fixtures must also include it; esbuild fixtures discard CSS imports.
- No ordinary modal-specific selector may redefine shell width, position, padding, border, radius, surface, shadow or backdrop. Named-session and deletion-review width overrides were removed. Settings remains the explicit full-window exception in `src/theme.css`; native file choosers are not app modals.
- Whole-window translucency uses a shared denser glass panel, restrained endpoint-continuous scrim, and scoped field/inset surfaces. Opaque/sidebar-only/Reduce Transparency preserve the original solid appearance. [Translucency](translucency.md#shared-modal-glass) owns density/contrast calibration and button tint credit; `.nimrod-modal` consumes those values here. No per-dialog glass overrides or blur filters.
- Native `<dialog>` and the existing Pi editor overlay share presentation, not lifecycle. Do not change native modality, acknowledgement, Escape/Back, request correlation, editor responses or focus restoration as part of styling. The editor remains the existing non-native overlay; this work does not claim improved modality/accessibility.
- Override the native dialog UA `max-width` cap in the shared shell; otherwise native dialogs and overlay cards differ by a few pixels at zoom/narrow widths.
- Scrollable bodies shrink within stack/form height limits; footer actions stay outside content scrolling. Shell overflow remains available for unusually long non-body content.

## Modal motion

- `src/modal-animation.ts` owns typed global preferences and root-local presentation tokens; `src/modal.css` owns live-shell entrances. `src/modal-motion.ts` owns the dedicated CRT beam and decorative exits for native `dialog.nimrod-modal` shells and Pi's existing `.modal-overlay` editor. Full-window Settings, native windows/file choosers and transcript disclosures are not animated by this feature.
- Global Appearance offers **Modal animation: None / Subtle (default) / CRT power-on**. Both animated styles expose **Duration (milliseconds)**, integer 0–2000, default 160. None hides its options without deleting the remembered duration. **Preview animation** opens a small ordinary native dialog over Settings; Close/Escape restore its launcher and do not close Settings. Duration is shared across styles and retained when switching; CRT does not change the default style or duration. Further styles/options can extend the typed preference reader and conditional options group.
- JSONC keys: `appearance.modalAnimation` (`none | subtle | crt`) and `appearance.modalAnimationDuration` (milliseconds). Frontend and Rust validate both. Global-only reads/writes use the existing queued JSONC/CAS/synchronization pipeline; project files reject these keys. Missing keys restore defaults; invalid external edits retain the last valid snapshot.
- Subtle fades in from 98% scale and 4px below its final position, using a short ease-out without overshoot. The backdrop fades alongside it. Exit uses the reverse endpoint at 75% of the configured entrance duration (rounded to milliseconds).
- CRT uses a separate full-width **2 CSS-pixel** beam, centered on the measured shell rectangle, with theme-accent background/glow. The live panel is revealed with a center-out clip path, not compressed or accent-filled; there is no giant inset shadow or panel-wide accent interpolation. `--vscode-focusBorder` supplies the accent, with progress-color/current-color fallback. The beam fades as untinted content reveals; settled modal surfaces/shadows remain unchanged. CRT exit plays the entrance clip frames and per-segment easing in reverse, including its line hold. The exact same beam frames are reused with reverse playback. The panel/layer never receives an opacity animation: only a separate backdrop fades (reversing its entrance). CRT closing takes **80%** of configured duration (rounded; 500 → 400 ms), while Subtle retains **75%**. No flicker, scanlines, sound or delayed input. Root `data-modal-animation` selects shared entrance tokens.
- Native/overlay show and controlled-close sites use the explicit shared `showModal` / `closeModal` / overlay helpers. The controller captures a detached visual snapshot before close, then performs the real close/removes the overlay class **synchronously**. Request settlement, return values, cancellation, focus and availability never wait for visual completion; no prototype patch, semantic close callback or replay is introduced. Document capture listeners additionally cover native Escape/cancel and default `method=dialog` submission, retain the pre-close snapshot until the **actual native `close` event**, respect `preventDefault`, and deduplicate helpers invoked by those handlers. Do not test the default outcome in a microtask: trusted input can checkpoint microtasks between listeners, before the default closes the dialog. A zero-delay task releases prevented/still-open captures after default processing; a closed dialog retains its capture for its queued close event. New opens/preferences/disposal clear pending captures and cleanup timers. Generation/epoch guards reject stale presentation after reopening/new dialogs.
- A short-lived inert, `aria-hidden`, pointer-transparent layer uses a **manual non-modal popover** for top-layer presentation, not CSS `overlay` retention or discrete transitions. Without popover support it portals into the remaining parent dialog (or document body). It never calls `showModal` or transfers focus. WAAPI animates the shell snapshot/backdrop for its style-specific exit duration (CRT 80%, Subtle 75%); no CSS support gate disables normal native exits. If decorative APIs/capture fail, real close still proceeds immediately.
- Snapshot IDs become `data-modal-snapshot-id`; scoped shadow styles rewrite ID selectors while retaining specificity. Live document queries, modal priority and selectors never see duplicate live controls. Values/checked state, scroll offsets, measured geometry including CSS zoom, inherited theme tokens and typography are retained. No original event listeners, autofocus/inline handlers, editable/tab stops, live application notice strip, scripts or embedded frames participate. Stylesheet serialization is cached per sheet/rule count; no transcript/history snapshots, stream observers or per-frame DOM polling.
- Remnants are removed on animation completion (with a duration + 100ms cleanup backstop), new modal opens, motion preference changes, reduced-motion changes, resize/pagehide and owner disposal. Queued beams carry opening generations/epochs. Cleanup only removes decorative nodes/animations, never closes/reopens/focuses a real dialog or runs its accepted action.
- `prefers-reduced-motion: reduce` forces both durations to zero without changing saved preferences; None/zero duration also produce immediate presentation. Changing preferences does not recreate dialogs or replay their content. Palette-to-picker and retained-permission page changes stay in their mounted shell without replaying its entrance; directional page motion is deferred.
- Root tokens apply at initial shared Settings-surface installation and on preference snapshots in project/global Settings windows. Duration edits in the focused field survive unrelated snapshots. Controls are hidden as one group in Project settings.
- Authored, **unrun** fixtures: `test/modal-animation.test.ts` (tokens/focus), `test/preferences.test.ts` and native preferences tests (defaults, validation, JSONC/global scope, external changes), `test/browser/modal-animation.spec.ts` (conditional options, retained duration including CRT, preview, cross-window sync, input/focus and reduced motion), `test/modal-motion.test.ts` (immediate controlled/native closure, isolated inert snapshots, editor overlay, values, prevented/duplicate cancellation, new-open cleanup, decorative failure, None/zero, preference/disposal/finish cleanup), `test/browser/modal-preview.spec.ts` (trusted Playwright Close/Escape input, visible native preview exit, focus, parent Settings and reopen cleanup), `test/browser/modal-crt.spec.ts` (dedicated beam/untinted clip reveal at 160 and 500 ms, native default submit with 80%-duration reversed CRT exit and no panel/layer opacity fade, focus and rapid reopen, reduced motion and no-popover parent-dialog fallback). Existing glass measurements request reduced motion to inspect final surface opacity. User trial of the previous implementation reported an accent flash at short durations and no observed native exit. The user subsequently confirmed actual-app Subtle dismissal works, narrowing the remaining report to preview; this follow-up changes native-default capture timing, not the working Subtle motion. Native macOS/Linux quality, zoom/stacking/focus/accessibility acceptance of the replacement remains pending.

## Confirmation actions

`src/dialog-actions.ts` shares plain action labels and non-visual `aria-keyshortcuts`. Buttons contain label text only; no Enter SVG, Esc text or hint-specific styling. Picker-row hints are unchanged. `Dialogs.confirm` accepts an optional action label after owner; shell Close/Restart provide explicit labels, Pi retains Confirm. Input/select calls clear shortcut metadata and reset the generic label.

`navigateDialogActions` shares footer-button navigation across host input/select/confirm dialogs, deletion review, keybinding recorder/reset dialogs and Pi's editor overlay. Unmodified Left/Up move backward and Right/Down move forward in DOM order, wrapping between enabled, non-hidden/non-inert Cancel and accept buttons. Navigation changes focus only, with no activation or scrolling; disabled Delete is skipped during loading. Repeated arrows can move focus; composing/keyCode-229 arrows are consumed without movement. Arrows from text fields, selects, the shortcut-recording input and other content retain their existing behavior; modified arrows are untouched. Palette pickers retain their existing list navigation (they have no Cancel/accept footer pair).

Host confirmations, populated deletion reviews and eligible keybinding resets focus the confirmation action. Enter honors Cancel focus (including descendant nodes), otherwise activates the enabled confirmation; Escape cancels. Repeated/composing/keyCode-229 Enter is consumed without activation. Native form return values/request correlation and close-time focus restoration remain unchanged. Key recording still captures shortcuts rather than treating Enter as Save. During async reset saving the existing click guards prevent duplicate save/cancel.

Deletion loading disables Delete, clears its Enter shortcut metadata and focuses Cancel. A visible loading-to-review transition preserves focus rather than moving it after the user has begun interacting; Enter on Cancel cancels both loading and populated review. Fresh ready-only reviews focus Delete. See session-deletion reference.

Unit fixtures cover all four arrow directions/wrapping, reversed DOM order, disabled/hidden/inert actions, modifiers, IME/repeats, editing controls, default/Cancel focus, plain labels/shortcut metadata and cleanup before input. Offline WebKit fixtures cover arrow navigation followed by Enter in temporary Close, deletion review and keybinding reset dialogs, default focus, absence of button hints, close restoration and retained drafts. The arrow-navigation additions have not been executed yet. Native visual acceptance and Linux verification remain pending.

Copilot denial feedback uses the existing host input dialog layered above its retained permission picker; the parent does not change size to become a text editor. `Dialogs.input` accepts an optional submit label (default **Confirm**, permissions use **Send denial**). Shared shell geometry, native topmost focus and input Enter/newline behavior remain authoritative; no feature-specific width/position or motion override is introduced; the shared modal motion applies. Cancellation/disposal revalidates the concrete permission owner before applying text. New retained-palette/permission unit, shell and offline-browser fixtures are authored unrun; native stacking/zoom/accessibility acceptance remains pending.

## Command rows

`PaletteOptions.commands()` requires a `detail` string; picker items retain optional metadata. Every shell command supplies a short explanatory description in `src/main.ts`, rather than a project path/current value/session title. `src/command-palette.ts` appends the effective-binding `<kbd>` inside `.palette-item-heading`, after the flexible title, and the `.palette-item-description` below it. Unbound commands have no shortcut placeholder. Both fields stay visually secondary on selected rows. Picker-specific rows/order and MRU behavior remain unchanged. Descriptions participate in existing text filtering.

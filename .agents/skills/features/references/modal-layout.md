# Shared modal layout and command rows

**Status: implemented.** This reference owns current specifications and implementation details. [Verification status](verification.md) separates fixture evidence from native acceptance; [historical records](history/feature-records.md#modal-layout) retain prior execution records.

## Specification and acceptance criteria

Ordinary dialogs share a shell, not identical content. Confirmation labels remain plain, arrow keys navigate enabled footer actions, Enter follows focused action/Cancel, Escape cancels, and loading review retains Cancel focus after late population.

## Contract and code map

- `src/modal.css` is the sole ordinary-modal shell authority: `.nimrod-modal`, `--modal-*` geometry/spacing/backdrop tokens, `.modal-stack`, `.modal-header`, `.modal-title`, `.modal-description`, `.modal-body`, `.modal-actions` and `.modal-overlay`.
- `index.html` applies it to command palette, host input/select/confirm and deletion review. `src/keybinding-editor.ts` applies it to the dynamically created recorder. `src/pi/resume-modal.ts` applies it to the retained renderer picker. `src/pi/transcript.html` applies it to Pi's editor card/overlay.
- `src/main.ts` imports the shared stylesheet after content styles. Offline browser/view fixtures must also include it; esbuild fixtures discard CSS imports.
- No ordinary modal-specific selector may redefine shell width, position, padding, border, radius, surface, shadow or backdrop. Named-session and deletion-review width overrides were removed. Settings remains the explicit full-window exception in `src/theme.css`; native file choosers are not app modals.
- Whole-window translucency uses a shared denser glass panel, restrained endpoint-continuous scrim, and scoped field/inset surfaces. Opaque/sidebar-only/Reduce Transparency preserve the original solid appearance. [Translucency](translucency.md#shared-modal-glass) owns density/contrast calibration and button tint credit; `.nimrod-modal` consumes those values here. No per-dialog glass overrides or blur filters.
- Native `<dialog>` and the existing Pi editor overlay share presentation, not lifecycle. Do not change native modality, acknowledgement, Escape/Back, request correlation, editor responses or focus restoration as part of styling. The editor remains the existing non-native overlay; this work does not claim improved modality/accessibility.
- Override the native dialog UA `max-width` cap in the shared shell; otherwise native dialogs and overlay cards differ by a few pixels at zoom/narrow widths.
- Scrollable bodies shrink within stack/form height limits; footer actions stay outside content scrolling. Shell overflow remains available for unusually long non-body content.

## Implementation checklist

Apply this to every new or modified ordinary modal, including previews and dynamically created dialogs:

1. **Reuse the existing interaction first.** Host input/select/confirmation dialogs use `Dialogs`; command-palette pickers use its existing page lifecycle rather than a new dialog. Their shared presentation already uses the helpers below.
2. **Use the shared shell.** Apply `.nimrod-modal` and the appropriate `.modal-*` structure from `src/modal.css`. Do not duplicate shell geometry, theme surfaces, animation styles, duration calculations or reduced-motion handling in feature code.
3. **Use the lifecycle helpers, not raw DOM mutations.** Import `showModal(dialog)` and `closeModal(dialog, result?)` from `src/modal-motion.ts` for every programmatic open/close path. The retained Pi editor overlay uses `showModalOverlay(overlay)` / `closeModalOverlay(overlay)` instead of manually adding/removing its `open` class. Do not call native `.showModal()` / `.close()` directly in ordinary modal feature code, including cancel, error and teardown paths. The CSS class alone is insufficient: helpers supply the CRT/Hologram beams, pre-close capture and stale-motion cleanup.
4. **Keep native defaults centralized.** Native `method=dialog` forms and Escape/cancel are supported by the shared controller; do not add per-modal animation listeners or duplicate request settlement. `showModal` installs the document controller lazily; a new standalone window/entry point must ensure that controller exists before native dismissal and dispose it with its window owner. Project/global Settings already own this installation. The [motion contract](#modal-motion) owns default-action timing and deduplication.
5. **Never gate semantics on animation.** Preserve the feature's validation, return values, request correlation and focus restoration. Do not await an animation or add a close delay before settling an action. Decorative snapshots must remain inert and cannot become a second interaction owner.
6. **Extend the relevant fixtures.** Cover controlled/programmatic close plus native form/Escape paths used by the feature, focus/parent-modal preservation, reopening during exit, and None/reduced motion. For browser default-action regressions, use trusted Playwright clicks/keys—not only `element.click()` inside `page.evaluate`, which can mask microtask/default-action ordering. Follow repository authorization rules before running validation.

**Exceptions:** full-window Project settings uses `installSettings` in `src/settings.ts`, not ordinary modal animation; it clears decorative remnants on navigation. Global Settings is a native window containing that page. Native OS file/directory choosers keep their platform lifecycle. These exceptions are not precedent for bypassing helpers in new ordinary dialogs.

## Modal motion

- `src/modal-animation-defaults.ts` owns the style defaults and exit-duration calculation used by preference decoding, Settings hints and the motion controller's no-stylesheet fallback; `src/modal.css` mirrors the baseline duration tokens (Subtle 500/375 ms; CRT 300/240 ms; Hologram 300/240 ms). `src/modal-animation.ts` owns typed global preferences and root-local presentation tokens; `src/modal.css` owns live-shell entrances. `src/modal-motion.ts` owns the dedicated CRT/Hologram beams and decorative exits for native `dialog.nimrod-modal` shells and Pi's existing `.modal-overlay` editor. Full-window Settings, native windows/file choosers and transcript disclosures are not animated by this feature.
- Global Appearance offers **Modal animation: None / Subtle (default) / CRT power-on / Hologram**. Animated styles expose a **Duration (milliseconds)** slider, 100–1500 ms in 10 ms steps with a live millisecond readout; defaults are **500 ms for Subtle / 300 ms for CRT/Hologram** when the duration key is absent. Native range keyboard controls remain available. Input updates the readout/accessible value immediately; change/release commits through existing global preference writes, never one write per drag frame. The slider stays enabled during saves, and revisions protect newer edits from older save completions or unrelated snapshots. None hides its options without deleting the remembered duration. **Preview animation** opens a small ordinary native dialog over Settings; Close/Escape restore its launcher and do not close Settings. Explicit duration overrides are shared across styles and retained when switching if already on the valid grid; absent duration follows the selected style's default without writing a duration override. None uses the Subtle default as its inactive fallback and hides options. Further styles/options can extend the typed preference reader and conditional options group.
- JSONC keys: `appearance.modalAnimation` (`none | subtle | crt | hologram`) and `appearance.modalAnimationDuration` (milliseconds). Frontend and Rust validate style/type and retain the old 0–2000 integer file-decoding range so existing JSONC remains readable. Effective durations are clamped to 100–1500 ms and rounded to 10 ms by `normalizeModalDuration`, including direct presentation calls. This does not rewrite settings on startup; the next slider commit writes the in-range value. None is the explicit instant-animation option, not a zero duration. Global-only reads/writes use the existing queued JSONC/CAS/synchronization pipeline; project files reject these keys. Missing keys restore defaults; invalid external edits retain the last valid snapshot.
- Subtle fades in from 98% scale and 4px below its final position, using a short ease-out without overshoot. The backdrop fades alongside it. Exit uses the reverse endpoint at 75% of the configured entrance duration (rounded to milliseconds).
- CRT uses a separate full-width **2 CSS-pixel** beam, centered on the measured shell rectangle, with theme-accent background/glow. The live panel is revealed with a center-out clip path, not compressed or accent-filled; there is no giant inset shadow or panel-wide accent interpolation. `--vscode-focusBorder` supplies the accent, with progress-color/current-color fallback. The beam fades as untinted content reveals; settled modal surfaces/shadows remain unchanged. CRT exit plays the entrance clip frames and per-segment easing in reverse, including its line hold. The exact same beam frames are reused with reverse playback. The panel/layer never receives an opacity animation: only a separate backdrop fades (reversing its entrance). CRT closing takes **80%** of configured duration (rounded; 500 → 400 ms), while Subtle retains **75%**. No flicker, scanlines, sound or delayed input. Root `data-modal-animation` selects shared entrance tokens.
- Hologram reveals the untinted live shell from top to bottom using a linear clip-path wipe. A separate 2px theme-accent line travels exactly one measured shell height, with a 16px, 25%-opacity gradient trail above it. The beam remains visible from the first edge to the last, without endpoint opacity ramps, flicker, loop, panel tint, text distortion or per-frame DOM polling. Default entrance is 300 ms; closing reverses the clip/beam frames in 240 ms (80%), without panel opacity fade. The controller freezes preparation at frame zero, adopts the live CSS reveal/backdrop (or supplies a WAAPI reveal fallback), and starts all Hologram effects together on one animation frame using the same document-timeline start time. Exit effects use that same grouped-start mechanism. A scoped ResizeObserver adjusts opening beam geometry/keyframes if content changes the shell's size, without restarting its timeline. Overlay scrims animate on their own pseudo-element rather than fading the panel's parent. If dismissed during entrance, exit beam travel starts at the captured reveal edge rather than jumping to the bottom. Shared `--modal-beam-accent` uses the theme's focus/progress fallback. Existing modal helpers own all lifetime, native default-action, inert snapshot, focus and reduced-motion behavior; no per-modal Hologram implementation is needed. Layout/zoom/native appearance still require platform acceptance.
- Native/overlay show and controlled-close sites use the explicit shared `showModal` / `closeModal` / overlay helpers. The controller captures a detached visual snapshot before close, then performs the real close/removes the overlay class **synchronously**. Request settlement, return values, cancellation, focus and availability never wait for visual completion; no prototype patch, semantic close callback or replay is introduced. Document capture listeners additionally cover native Escape/cancel and default `method=dialog` submission, retain the pre-close snapshot until the **actual native `close` event**, respect `preventDefault`, and deduplicate helpers invoked by those handlers. Do not test the default outcome in a microtask: trusted input can checkpoint microtasks between listeners, before the default closes the dialog. A zero-delay task releases prevented/still-open captures after default processing; a closed dialog retains its capture for its queued close event. New opens/preferences/disposal clear pending captures and cleanup timers. Generation/epoch guards reject stale presentation after reopening/new dialogs.
- A short-lived inert, `aria-hidden`, pointer-transparent layer uses a **manual non-modal popover** for top-layer presentation, not CSS `overlay` retention or discrete transitions. Without popover support it portals into the remaining parent dialog (or document body). It never calls `showModal` or transfers focus. WAAPI animates the shell snapshot/backdrop for its style-specific exit duration (CRT/Hologram 80%, Subtle 75%); no CSS support gate disables normal native exits. If decorative APIs/capture fail, real close still proceeds immediately.
- Snapshot IDs become `data-modal-snapshot-id`; scoped shadow styles rewrite ID selectors while retaining specificity. Live document queries, modal priority and selectors never see duplicate live controls. Values/checked state, scroll offsets, measured geometry including CSS zoom, inherited theme tokens and typography are retained. No original event listeners, autofocus/inline handlers, editable/tab stops, live application notice strip, scripts or embedded frames participate. Stylesheet serialization is cached per sheet/rule count; no transcript/history snapshots, stream observers or per-frame DOM polling.
- Remnants are removed on actual animation completion/cancellation, new modal opens, motion preference changes, reduced-motion changes, hidden-document visibility, resize/pagehide and owner disposal. No wall-clock completion backstop may truncate a delayed, running or paused effect. One-shot start frames and geometry observers are cancelled/disconnected with their layer; hidden windows do not create effects. The zero-delay native-default capture cleanup is separate and never decides visual completion. Queued beams carry opening generations/epochs. Cleanup only removes decorative nodes/animations, never closes/reopens/focuses a real dialog or runs its accepted action.
- `prefers-reduced-motion: reduce` forces both durations to zero without changing saved preferences; None also produces immediate presentation; a legacy zero duration normalizes to the 100 ms minimum rather than disabling an animated style. Changing preferences does not recreate dialogs or replay their content. Palette-to-picker and retained-permission page changes stay in their mounted shell without replaying its entrance; directional page motion is deferred.
- Root tokens apply at initial shared Settings-surface installation and on preference snapshots in project/global Settings windows. In-progress slider edits and newer commits survive unrelated snapshots and older save completions. Controls are hidden as one group in Project settings.
- Hologram fixtures are authored **unrun**: preference/default/native validation, controller scan geometry/reversal/partial-close/cleanup, `test/browser/modal-hologram.spec.ts` sampled reveal/beam alignment and reverse exit at CSS zoom, and trusted Close/Escape preview cases. Delayed-first-paint synchronization, full-edge beam visibility, no wall-clock truncation, resized-shell alignment and slider live/readout/keyboard/commit coverage are also authored unrun. Shared-range/step controls and legacy read-normalization without automatic writes are covered by additional authored, unrun fixtures. User-reported Hologram smoothness and native completion remain unaccepted; no native Hologram acceptance/build/launch is claimed.
- Authored, **unrun** fixtures: `test/modal-animation.test.ts` (tokens/focus), `test/preferences.test.ts` and native preferences tests (defaults, validation, JSONC/global scope, external changes), `test/browser/modal-animation.spec.ts` (conditional options, retained duration including CRT, preview, cross-window sync, input/focus and reduced motion), `test/modal-motion.test.ts` (immediate controlled/native closure, isolated inert snapshots, editor overlay, values, prevented/duplicate cancellation, new-open cleanup, decorative failure, None/legacy-duration bounds, preference/disposal/finish cleanup), `test/browser/modal-preview.spec.ts` (trusted Playwright Close/Escape input, visible native preview exit, focus, parent Settings and reopen cleanup), `test/browser/modal-crt.spec.ts` (dedicated beam/untinted clip reveal at 160 and 500 ms, native default submit with 80%-duration reversed CRT exit and no panel/layer opacity fade, focus and rapid reopen, reduced motion and no-popover parent-dialog fallback). Existing glass measurements request reduced motion to inspect final surface opacity. User trial of the previous implementation reported an accent flash at short durations and no observed native exit. The user subsequently confirmed actual-app Subtle dismissal works, narrowing the remaining report to preview; this follow-up changes native-default capture timing, not the working Subtle motion. Native macOS/Linux quality, zoom/stacking/focus/accessibility acceptance of the replacement remains pending.

## Confirmation actions

`src/dialog-actions.ts` shares plain action labels and non-visual `aria-keyshortcuts`. Buttons contain label text only; no Enter SVG, Esc text or hint-specific styling. Picker-row hints are unchanged. `Dialogs.confirm` accepts an optional action label after owner; shell Close/Restart provide explicit labels, Pi retains Confirm. Input/select calls clear shortcut metadata and reset the generic label.

`navigateDialogActions` shares footer-button navigation across host input/select/confirm dialogs, deletion review, keybinding recorder/reset dialogs and Pi's editor overlay. Unmodified Left/Up move backward and Right/Down move forward in DOM order, wrapping between enabled, non-hidden/non-inert Cancel and accept buttons. Navigation changes focus only, with no activation or scrolling; disabled Delete is skipped during loading. Repeated arrows can move focus; composing/keyCode-229 arrows are consumed without movement. Arrows from text fields, selects, the shortcut-recording input and other content retain their existing behavior; modified arrows are untouched. Palette pickers retain their existing list navigation (they have no Cancel/accept footer pair).

Host confirmations, populated deletion reviews and eligible keybinding resets focus the confirmation action. Enter honors Cancel focus (including descendant nodes), otherwise activates the enabled confirmation; Escape cancels. Repeated/composing/keyCode-229 Enter is consumed without activation. Native form return values/request correlation and close-time focus restoration remain unchanged. Key recording still captures shortcuts rather than treating Enter as Save. During async reset saving the existing click guards prevent duplicate save/cancel.

Deletion loading disables Delete, clears its Enter shortcut metadata and focuses Cancel. A visible loading-to-review transition preserves focus rather than moving it after the user has begun interacting; Enter on Cancel cancels both loading and populated review. Fresh ready-only reviews focus Delete. See session-deletion reference.

Unit fixtures cover all four arrow directions/wrapping, reversed DOM order, disabled/hidden/inert actions, modifiers, IME/repeats, editing controls, default/Cancel focus, plain labels/shortcut metadata and cleanup before input. Offline WebKit fixtures cover arrow navigation followed by Enter in temporary Close, deletion review and keybinding reset dialogs, default focus, absence of button hints, close restoration and retained drafts. The arrow-navigation additions have not been executed yet. Native visual acceptance and Linux verification remain pending.

Copilot denial feedback uses the existing host input dialog layered above its retained permission picker; the parent does not change size to become a text editor. `Dialogs.input` accepts an optional submit label (default **Confirm**, permissions use **Send denial**). Shared shell geometry, native topmost focus and input Enter/newline behavior remain authoritative; no feature-specific width/position or motion override is introduced; the shared modal motion applies. Cancellation/disposal revalidates the concrete permission owner before applying text. New retained-palette/permission unit, shell and offline-browser fixtures are authored unrun; native stacking/zoom/accessibility acceptance remains pending.

## Command rows

`PaletteOptions.commands()` requires a `detail` string; picker items retain optional metadata. Every shell command supplies a short explanatory description in `src/main.ts`, rather than a project path/current value/session title. `src/command-palette.ts` appends the effective-binding `<kbd>` inside `.palette-item-heading`, after the flexible title, and the `.palette-item-description` below it. Unbound commands have no shortcut placeholder. Both fields stay visually secondary on selected rows. Picker-specific rows/order and MRU behavior remain unchanged. Descriptions participate in existing text filtering.

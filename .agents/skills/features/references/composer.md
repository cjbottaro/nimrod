# Composer delivery and keyboard hints

**Status: implemented.** This reference owns current specifications and implementation details. [Verification status](verification.md) separates fixture evidence from native acceptance; [historical records](history/feature-records.md#composer) retain prior execution records.

## Specification and acceptance criteria

Idle sends and busy Enter steering clear the editable draft immediately, independently of acknowledgement. Busy-only explicit follow-up queues and immediate idle/steering pending turns reconcile without duplicate user messages, result-driven transcript scrolling or inferred consumption. Local Send navigation follows the [auto-follow preference](transcript-interaction.md#auto-follow-after-sending). Apply the [optimistic interaction policy](architecture.md#optimistic-interaction-policy); Send also updates sidebar recency immediately.

## Code map

- `src/pi/composer-dom.ts`: keyboard delivery mapping and hint ordering.
- `src/pi/webview-client.ts`: busy-state hints, keyboard submission, send-local image preparation, receipt-only error reporting and compaction lock.
- `src/pi/session.ts`: authoritative session-state gate and Pi prompt RPC.
- `src/pi/steering-transcript.ts`: live pending-turn projection, queue reconciliation and user-turn key aliases.
- `src/pi/webview-client.ts`: applies every ordered snapshot before coalesced painting, including while hidden; hidden views retain the latest pending presentation for synchronous reveal catch-up. Queue/consumption/receipt/recovery observations are never deferred or discarded. Patches pending-status labels in the existing user article.

Image attachment behavior and its text-only queue recovery boundary are covered in [Image paste](image-paste.md). Error/uncertainty presentation follows the [error presentation policy](error-presentation.md); this reference owns delivery semantics, not a separate error surface.

## Contract

- Idle: Enter sends normally; Option-Enter also sends normally, never queues. Hints: `Enter to send · Shift+Enter for newline`.
- Main agent working: Enter steers; Option-Enter queues a follow-up. Hints: `Enter to steer · Option-Enter to queue · Shift+Enter for newline`.
- Option is the macOS name for the Alt modifier (`KeyboardEvent.altKey`); Linux uses Alt+Enter. The current hint text uses the macOS label.
- Shift+Enter and IME input are not consumed by submission mapping.
- The controller sends `streamingBehavior: followUp` only for explicit `followUp` delivery while its main agent is busy. All other prompts include `steer`, preserving idle-to-busy race handling. If the controller is already idle after a busy renderer snapshot, the submission uses the ordinary steering fallback.
- Compaction locks submission and replaces keyboard hints with its cancellation hint. Background-only activity does not enable queueing.
- Send captures text and starts all image reads locally, then `clearDraft` consumes editable text/attachments synchronously. `ViewHost.promptSubmitted` synchronously notifies the shell of local message intent (ordinary, steering, follow-up and prompt slash expansions, excluding `/name` and `/compact`); it carries no payload/receipt, retains no submission state and fires before image preparation completes. The shell advances recency once and scrolls the current All/Working list to the top; Unread retains arrival order and reading position. Another prompt may be sent before its RPC result; only image preparation briefly serializes payload dispatch. Receipts update steering labels or report failures, never modify the current draft, including identical retyping/re-pasting. Failure/uncertainty reports session-local notices above the transcript pane; no recovery copy, Write a new message action or uncertainty-specific gate. Availability/compaction/deletion guards remain. Local validation before clearDraft keeps the editable draft.

## Pending user turns in the transcript

- Idle and busy plain-text submissions (normal, steer or followUp) create a local user preview before posting the prompt. Image turns create their preview once local image-byte preparation completes, also before posting; no Pi receipt/event is required. Ordinary previews have no delivery label. Explicit busy steering previews show only Steering until a matching authoritative user event or an error. RPC acceptance and queue removal do not remove or restart that shimmer; there is no intermediate label change. Steering remains non-sticky. Explicit follow-up previews show only Queued while sending/queued, with no label change at enqueue acknowledgement. Both labels omit ellipses and match the historical TOOL: BASH header treatment: inherited system-UI font family, .78em status size, normal weight, CSS uppercase and .05em letter spacing. They retain the left-to-right text shimmer; uppercase/spacing apply only to the pending labels, including reduced-motion presentation, not outcome/error labels. Transport sending/accepted/consumed distinctions remain internal. Errors/cancellation/uncertainty/disconnect retain their existing non-animated outcome labels. Normal idle submissions (including idle-to-busy races) never acquire a steering label. Slash commands are excluded because controls/expansions need not produce a literal user message. Authoritative queue snapshots also display steering text with Steering, including slash text, but never synthesize queue membership from acknowledgement. Matching normal idle previews keep their no-label presentation even when adopted by a steering queue.
- Previews append after all current live assistant/tool output. Actual user events adopt the preview's DOM key and authoritative position, removing its lifecycle label. Image prompts with Pi's ordered started-preflight correlation adopt authoritative normalized content by submission ID, not by caption or unchanged bytes; [Image paste](image-paste.md#invariants) owns that contract and fallback limitations. Existing user history is marked seen before submissions; only newly observed user keys can consume previews. Text matching trims outer whitespace, joins text blocks, and consumes equal occurrences FIFO within each delivery kind rather than collapsing duplicates; matching steering takes precedence over an identical follow-up, reflecting Pi's delivery order.
- Apply queue/message observations on every host snapshot, not only on rendered frames: queue removal, consumption and clear_queue recovery can all occur within one frame. Queue removal alone is not proof of consumption, so retain the preview until a matching user message or explicit recovery. Definitive rejection/cancellation retains local turns marked Not sent/Cancelled and excludes them from subsequent user-event/queue/recovery matching. Already-authoritative Pi user turns remain untouched.
- Sending remains internally tracked until the RPC receipt, even if a queue snapshot arrives first. A user event may settle the preview before a late receipt but must never acknowledge/clear the composer. Rejected/cancelled local turns remain marked; unknown previews remain marked. Disconnect distinguishes unknown acceptance from accepted but unconfirmed delivery. Uncertain transcript previews remain marked independently of the composer; no notice dismissal or new draft implies consumption.
- Steering and follow-up text leave the status area; their authoritative pending counts remain. Follow-ups form one sticky stack at the bottom of the transcript pane while sending/queued, including while reading older history; streaming output stays above them. The stack has an opaque backing solely to mask output passing underneath and a bounded, independently scrolling height for long/multiple messages. Queued articles use ordinary user-turn padding, accent, background and inter-turn spacing; there is no queue separator, extra gap or compact message styling. Pi enqueue acknowledgement does not unpin: an authoritative matching user event adopts the existing article at Pi's transcript position and removes the queue label/stickiness. Queue removal alone never unpins. Rejection, cancellation, unknown acceptance or disconnect unpins the retained local turn with its existing lifecycle label. Existing recovered Restore controls remain unchanged. Clear_queue recovery removes matching pending previews by occurrence and delivery kind, including image-bearing follow-up previews matched against Pi's text-only queue recovery (steering retains its existing image-recovery exclusion) and retains exact nonempty returned text in existing composer recovery. Image-only empty strings do not create blank Restore rows.
- Projection/aliases are renderer-local, not persisted to Pi or draft storage. Explicit sessionReset replaces the projector. Transport request correlation is runtime-only; composer state has no submission lifecycle. Retired persisted submissions are ignored and removed on the next write; reload restores only editable drafts/queue recovery, without reconstructing fictitious history or inferring acknowledgement.
- Reconciliation is intentionally conservative: Pi's user messages and queues have no submission IDs. Expanded/rewritten user content without explicit started-image correlation cannot safely be matched by identity, and externally cleared queues without Nimrod's recovery response cannot prove delivery. Do not infer either from counts/idle state.
- Rendering uses the existing TranscriptScroll capture/request path. Local Send may explicitly navigate under the [auto-follow preference](transcript-interaction.md#auto-follow-after-sending), without changing focus; no transcript render for ordinary draft keystrokes. Pending-label changes preserve assistant/tool nodes and disclosure state. The shimmer is CSS-only on a text-width span, without per-frame JS, layout growth or live-region churn. Streaming patches and successful steering/follow-up receipts retain that span/animation. Reduced motion renders a static readable label; hidden/inactive session views and hidden documents pause the animation.

## Typing hot path

Draft-only edits retain status/control DOM and update the in-memory draft immediately. Native CSS content sizing is used where supported, otherwise one coalesced pre-paint measurement uses the latest text. Hide/dispose cancels pending sizing; selection sizes the latest draft. The fallback retains the shell-height hold/floor measurement so it cannot clamp transcript reading during measurement. Send/Stop retains its SVG unless the action changes.

Draft persistence, debounce, immediate clearing, ignored legacy drafts, image references and the performance fixture are documented in [Native drafts](native-drafts.md). The original baseline performed 160 input-handler geometry reads and 800 status/button mutations for 80 characters; the current supported-WebKit fixture performs neither, and no localStorage writes. Timings remain diagnostic, not native input-to-paint acceptance.

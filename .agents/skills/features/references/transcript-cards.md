# Transcript cards

**Status: implemented.** This reference owns current specifications and implementation details. [Verification status](verification.md) separates fixture evidence from native acceptance; [historical records](history/feature-records.md#transcript-cards) retain prior execution records.


## Specification and acceptance criteria

One mounted card per invocation survives placement/lifecycle updates, preserving manual disclosure, output reading position and connected indicator identity. Full raw content remains accessible without summary hover tooltips.

## Code map and invariants

- `src/pi/tool-call.ts`: common partial tool-call merge and standalone-envelope conversion. Both reducer and renderer parse standalone inputs through this model, so input previews match assistant-embedded cards. Lifecycle rank is running → finished → result; stale earlier-phase events cannot rewind status/output/errors. Complete late assistant arguments remain authoritative.
- `src/pi/conversation-index.ts`, `transcript-updates.ts`: session-local tool-location indexes, content-only dirty call IDs/row revisions and weak presentation caches. Normal tool-output publication/painting does not project or serialize historical/unrelated rows. Dirty and full rows share `tool-progress.ts::projectToolRow` for result-processing/interruption phases; only full projection inserts the parallel-tools overview. Full authoritative messages are lazy; structural/progress/history/queue changes, revision gaps, local optimistic operations and recovery retain full reconciliation. See [incremental rendering](../../performance-optimizations/references/incremental-transcript.md) for remaining array-copy/cumulative-protocol costs and unrun fixtures.
- `src/pi/reducer.ts`: execution/result upserts and assistant-content reconciliation by `toolCallId`. Standalone `role: "tool"` messages remain a placement envelope, not a different card model. Missing assistant content stays standalone; matching start/delta/end/history content consumes only that ID's envelope. Repeated toolcall_start retains existing execution state.
- `src/pi/webview-client.ts`: per-view tool-node registry keyed `tool:<id>`, falling back to placement-scoped keys only for missing IDs. Creating from either envelope or assistant content reuses the same details node on placement changes; manual disclosure, disclosure timers, indicator identity and per-card output inspection survive. Clear registry on explicit session reset/dispose and prune removed cards after reconciliation. Never share this registry across sessions. Capture/restore output scroll per card, not per assistant article (an article can contain multiple tools).
- `src/pi/transcript-presentation.ts`: standalone tools have an accessible article label but no redundant visible `TOOL: …` prefix.
- `src/pi/tool-card.ts`: core incremental tool-card shell, indicator/ARIA, raw inputs and keyed output rendering. Per-shell `CardRendererController` routes creation and every patch through validated presentation; unsupported/failing renderers latch to raw fallback without resetting sibling shells. View removal/reset/disposal releases instances.
- `src/pi/card-renderer.ts`, `card-plugins/`: shared mounted DOM instance contract (with a pure-presentation adapter), per-built-in tool/reasoning/parallel implementations and explicitly trusted executable/optional declarative tool catalog. The standalone `src/card-plugin-api.ts` owns supported types; plugin callbacks receive immutable data snapshots. [Card plugins](card-plugins.md) owns matching, loading and API scope. Tool selection is fixed per mounted shell; missing/incompatible/failed explicit renderers use retained raw recovery. Executable trust removal blocks managed callbacks/actions and disposes to raw recovery on the next event/update; it is not a sandbox or a global-code undo operation. `tool-presentation.ts` remains a compatibility export.
- Edit sections are input-backed line-diff previews, not applied-file diffs. Their compact toolbar shows change counts, multi-edit position when needed, Wrap and Copy; unchanged lines remain context. Raw inputs follow the preview. Routine completed output remains in a closed Raw output disclosure; running/error/stopped output remains prominent. Generic cards retain their existing raw-input position. Raw inputs/Pi output remain readable. Plugins explicitly register keyed output viewports; core retains per-viewport inspection and lifecycle caps. Custom DOM also retains independent raw recovery when it omits raw sections.
- `src/pi/card-shell.ts`: disclosure and existing live-output scroll helpers, re-exported by `tool-card.ts` for compatibility.
- `src/pi/tool-disclosure.ts`: qualifying-update delay, minimum open dwell and manual-choice precedence.
- `src/pi/reasoning-card.ts`, `parallel-card.ts`: core shell/indicator/disclosure rendering around bundled presentation; view removal/reset/disposal releases instances. Reasoning retains unchanged Markdown nodes but replaces them when text changes; do not claim preservation of focused inner nodes across changed Markdown.
- Card summaries, indicators and previews have no `title` attributes: hovering does not show native tooltips, including after streaming/lifecycle updates.
- Preserve summary `aria-label` status descriptions, visible previews, raw inputs and expanded reasoning. Full content remains available by expanding the disclosure rather than hovering.
- Code Copy/Pop out button tooltips and status/composer controls are unaffected.
- Preserve connected spinner/disclosure nodes, manual toggle precedence, automatic disclosure timing and output scrolling; see [transcript interaction](transcript-interaction.md) and the disclosure contract below.

Each Pi built-in selects its own metadata-matched mounted plugin; [card plugins](card-plugins.md#built-in-tool-dogfooding) owns the IDs, matching and implementation map. Read summaries can show requested line ranges, and write bodies show literal input-backed **Requested content** alongside Pi output, not a claim of successful execution. File/search/list output remains literal. The shared generic fallback/override remains available for unknown/custom tools.

## Console-style command output

- The dedicated `nimrod.bash` plugin for Bash/shell/terminal cards (including normalized names such as `functions.bash`) opts into `CardSection.format: 'console'` for both execution and result sections. Other default tools, raw fallback and exact Raw output recovery remain literal. Plugins may explicitly request console sections through the shared presentation adapter; no private bundled renderer capability.
- `src/pi/console-output.ts` interprets SGR standard/bright/256/RGB foreground/background, bold/dim/italic/underline/strike/inverse/conceal and resets; CR/CRLF, backspace, eight-column tabs, CSI erase-line (`K`), relative cursor movement (`A/B/C/D`) and absolute column (`G`/backtick). Vertical movement is constrained to existing log lines; horizontal control positioning is capped at 16,384 to bound synthetic padding, not source text.
- OSC/DCS/control strings and unsupported modes/commands are consumed without title, clipboard, link, navigation or other side effects. Incomplete escapes carry across cumulative snapshots; no source HTML is parsed. This is not a PTY/full-screen emulator: alternate screens, erase-screen, absolute row positioning, terminal resizing and precise wide/combining glyph cursor geometry are out of scope. Pi output/truncation remains authoritative.
- Cumulative append snapshots consume only the suffix, preserving parser/style state. `output-source.ts` creates source tokens at card rendering, without reducer/envelope propagation or backward snapshot links; rendering validates only coalesced endpoints and shares the prefix comparison with raw recovery. Intermediate unpainted chunks do not trigger prefix scans; untracked snapshots validate conservatively. Replacement/truncated/final snapshots that are not extensions reset the parser and rebuild content inside the same viewport. Unchanged snapshots do no console DOM work. Control-free logs append to retained text nodes and scan only new bytes for controls. ANSI line appends retain text/style runs; cursor overwrite/erase rebuilds affected line children, preserving unaffected lines. A first transition from literal logs to control interpretation replays prior source once. Format switches release cached parsers.
- Existing `DomCardController` keyed viewport and outer transcript/card scroll owners remain authoritative. No timers, asynchronous rendering, focus changes, output-cap changes or hidden-view bypass. Rendered colors use managed theme terminal variables; missing colors use renderer fallbacks, so theme switches do not require output replay.
- Pure presentation adapters and core fallback reuse registered outputs and cached source/format information, so `syncRawRecovery` does not read accumulated Bash DOM `textContent`. Arbitrary mounted DOM plugins retain compatibility inspection even when using `renderPresentation`; source metadata is not proof that later synchronous customization left literal content intact. When rendering changes the bytes (or managed nonliteral coverage is not established), the existing independent Raw output disclosure retains unmodified execution/result strings and appends literal suffixes. Disclosure identity/open state survives updates. Unchanged arguments/raw inputs are not reserialized or replaced. Plain managed text uses the same append helper; Markdown/diff parsing semantics remain unchanged.
- Added fixtures: `test/console-output.test.ts` covers parsing, split escapes/Unicode, replacement snapshots, safe literal markup/control strings, theme-variable styles, untouched line identity, no-op updates, format switches and live/final card identity/focus/inspection/raw recovery. `test/browser/console-output.spec.ts` covers real-layout independent inspection, final caps, styled text and exact recovery; hidden-session fixtures now include colored output. These fixtures have **not been run** for this change; no native/platform acceptance is claimed.

## Disclosure specification and acceptance criteria

- Generation, execution output, final result and result processing are distinct states; late earlier-phase updates must not rewind completion. A tool-result content update preserves the current thinking overlay until progress ends it; late content preserves the stopped overlay after interruption. Both incremental and full rendering apply this same policy.
- Cards start closed. Only sustained nonempty execution output qualifies for auto-open after `TOOL_AUTO_DISCLOSURE_MS` (500ms); a final result alone never qualifies.
- Manual open/close choices override automatic lifecycle disclosure. Auto-open has a 500ms minimum visible dwell; preserve the scheduler rather than replacing it with result-driven opening. Hidden-session presentation pauses remaining qualifying delay and dwell without toggling stale cards. Catch-up supplies the latest lifecycle before timers resume; unseen still-running output starts its delay on reveal, while work that starts/finishes entirely hidden never opens from its final result. Existing manual disclosure/card identity survives switching.
- Live/final output viewports retain their eight-line/sixteen-line visual caps; these limit viewport height, not source content. Full raw inputs/results remain readable.
- Placement changes must reuse one call-ID-keyed mounted shell, preserving connected indicators, disclosure timers and independently inspected output offsets.
- Safe Markdown/code rendering, accessibility, Copy/Pop out and summary tooltip policy remain unchanged.

## Tests and remaining acceptance

`test/transcript-updates.test.ts` and `test/native-view.test.ts` add full-versus-incremental lifecycle comparisons for standalone/embedded rows, coalesced/hidden/gapped delivery and retained phase indicators/output caps. `test/dom-card-renderer.test.ts` adds exact raw recovery after custom plugins overwrite helper-rendered output in the same or a later update. These review-fix fixtures are authored but unrun.

`test/tool-call.test.ts`, `test/tool-input-lifecycle.test.ts`, `test/native-view.test.ts` and `test/transcript-presentation.test.ts` cover both source orders, results-first history, missing assistant content, duplicate updates, late assistant input precedence, stable DOM identity during placement changes, manual disclosure, session reset and independently preserved multi-tool output inspection. `test/tool-card.test.ts` and `test/reasoning-card.test.ts` assert absence of tooltip attributes on initial rendering and updates while retaining accessible status labels. These DOM tests do not establish native hover acceptance; validate the packaged app visually without launching or interrupting the user's window automatically.
